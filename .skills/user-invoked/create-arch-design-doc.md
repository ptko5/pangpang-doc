------------------------------------------------------------------------------------------------------------------------------------------------

## 执行步骤

### Step 1: 接收主题参数

- 必填：`<主题>` - 架构设计的名称，如「用户服务架构设计」「分库分表方案」

- 可选：业务背景描述、性能指标要求、约束条件

### Step 2: 创建文档

**目标目录**：`/workspace/docs/03-技术笔记/架构设计/`

**文件名**：`<主题>.md`（kebab-case 处理）

**文档骨架**：

```markdown
# <主题>

## 1. 文档说明

| 属性 | 说明 |
|------|------|
| 文档版本 | V1.0 |
| 生效日期 | YYYY-MM-DD |
| 适用范围 | 相关业务模块 |
| 作者 | 架构组 |

---

## 2. 背景与目标

### 2.1 业务背景
（当前系统现状、业务发展预期）

### 2.2 现存问题
（遇到的瓶颈、痛点、技术债）

### 2.3 设计目标
（功能性目标 + 非功能性目标：性能、可用性、可扩展性、可维护性）

### 2.4 约束条件
（技术栈限制、历史包袱、合规要求、时间窗口）

---

## 3. 方案对比

### 3.1 备选方案列表

| 方案 | 描述 |
|------|------|
| 方案 A： | |
| 方案 B： | |
| 方案 C： | |

### 3.2 多维度对比

| 维度 | 方案 A | 方案 B | 方案 C |
|------|--------|--------|--------|
| 开发成本 | | | |
| 运维复杂度 | | | |
| 性能表现 | | | |
| 可扩展性 | | | |
| 故障恢复能力 | | | |
| 与现有系统兼容度 | | | |
| **推荐度** | | | |

### 3.3 方案选型结论
（明确选中方案 + 核心理由 + 放弃其他方案的原因）

---

## 4. 详细设计

### 4.1 总体架构图
（使用 Mermaid 或引用 assets/images/ 下的图片）

### 4.2 核心模块设计
| 模块 | 职责 | 关键接口 |
|------|------|---------|
| | | |

### 4.3 数据设计
- 数据库表结构（CREATE TABLE）
- 缓存设计（Key 设计、过期策略）
- 数据流转图

### 4.4 接口设计
| 接口 | Method | 路径 | 请求参数 | 返回值 |
|------|--------|------|---------|--------|
| | | | | |

### 4.5 异常处理
- 错误码定义
- 降级策略
- 重试机制

### 4.6 部署方案
- 部署架构
- 资源配置（CPU/内存/实例数）
- 灰度发布策略

---

## 5. 风险评估

| 风险项 | 概率 | 影响 | 缓解措施 |
|--------|------|------|---------|
| 方案复杂度高，落地周期长 | 中 | 高 | 分阶段实施，每阶段可回滚 |
| | | | |

---

## 6. 落地检查清单

| 序号 | 检查项 | 负责人 | 状态 |
|------|--------|--------|------|
| 1 | 方案评审是否通过 | 架构师 | ⬜ |
```

### Step 3: 填充内容

根据设计主题：

1. 第 2 章：明确 SMART 目标（Specific, Measurable, Achievable, Relevant, Time-bound）
2. 第 3 章：至少 2 个备选方案，对比维度不少于 6 个
3. 第 4 章：包含实际代码示例（SQL、接口定义、伪代码）
4. 第 4.1 章：使用 Mermaid 语法画架构图
5. 第 5 章：不少于 4 项风险，覆盖技术/人力/时间/业务维度

### Step 4: 执行纪律检查

1. `check-doc-structure` → 结构完整性
2. `check-markdown-format` → 格式合规性
3. `check-chinese-typography` → 中文排版
4. `check-doc-placement` → 确认在架构设计目录下
5. `check-content-quality` → 无占位符空章节
6. `generate-checklist` → 生成第 6 章检查清单

### Step 5: 输出结果

```
✅ 架构设计文档创建完成
📄 路径：docs/03-技术笔记/架构设计/<主题>.md
📊 纪律检查：全通过
⚠️  请人工评审：第 3.3 章选型结论、第 4 章详细设计的技术可行性
```

## 失败处理

| 失败场景          | 处理方式                        |
| ------------- | --------------------------- |
| 缺少具体业务背景      | 询问：请补充业务场景、QPS 指标、数据量等上下文   |
| 详细设计缺少代码示例    | 使用伪代码占位，标注「需开发人员补充具体实现」     |
| Mermaid 图无法绘制 | 描述架构图结构，提示用户后续补充图片到 assets/ |
