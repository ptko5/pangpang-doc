## 检查规则

### R1: 禁止占位符文本（禁止）

以下字符串 **严禁** 出现在最终提交的文档中：

| 禁止文本（正则匹配）                        | 说明                                 |
| --------------------------------- | ---------------------------------- |
| `（待补充）` / `（待完善）` / `待补充` / `待完善` | 半成品占位标记                            |
| `本文档正在建设中` / `文档正在建设中`            | 整文档占位                              |
| `TODO`（大小写敏感，非代码块中）               | 待办项未完成                             |
| `FIXME`（大小写敏感，非代码块中）              | 已知问题未修复                            |
| `TBD` / `TBA`（非代码块中）              | To Be Determined / To Be Announced |
| `N/A`（在文档说明表格的属性值中，非技术含义）         | 文档属性未填写                            |
| `<xxx>`（尖括号占位符，如 `<功能名>`、`<作者>`）  | 模板变量未替换                            |

**豁免**：

- 反引号包裹内（示例代码中的 `<占位>` 语法说明可以接受）

- Mermaid 图代码中的节点占位

- 技术文档中明确说明「这是示例占位」的上下文

### R2: 禁止空章节（禁止）

二级标题（`##`）及以上的章节，如果：

1. 该标题下没有任何文本内容（下一个标题之前的区域为空，或只有空行）
2. 或者该标题下只有一行无意义的占位文本

则判定为空章节。

**判定逻辑**：

```
对每个 H2/H3 标题：
  提取从该标题下一行到下一个同级或更高级标题之间的所有行
  去除空行、去除仅含 Markdown 格式符（---、***）的行后
  如果行数 = 0 → 空章节违规
  如果行数 = 1 且该行匹配 R1 中的占位符正则 → 空章节违规
```

### R3: 文档整体内容不得过短（强制）

文档正文（去除标题、表格、代码块后的纯文本字符数）不得少于：

- **规范类文档（00-开发规范/）**：≥ 1000 字

- **方案/调研类（03-技术笔记/架构设计、新技术调研）**：≥ 1500 字

- **问题排查类（03-技术笔记/问题排查）**：≥ 500 字

- **其他类**：≥ 300 字

**豁免**：

- `04-项目模板/` 下的模板文档（模板本身可以简短）

- README.md 索引型文档

- 纯代码示例型文档

### R4: 规范级文档必须包含落地检查清单（强制）

`00-开发规范/` 下的文档必须包含标题为「落地检查清单」的章节（通常在末尾），
且清单中至少包含 5 项检查项（表格形式，含「序号」列）。

原因：规范不是摆样子，必须能对照执行。

### R5: 技术调研类文档必须包含方案对比（强制）

`03-技术笔记/新技术调研/` 下的文档必须包含 **方案对比分析** 章节，
且对比维度不少于 5 行、对比方案不少于 2 列。

***

## 自动修复逻辑

**can-autofix = false**

原因：

- 占位符意味着内容缺失，AI 无法凭空补全业务语义正确的内容

- 空章节需要补充实际内容

- 内容过短意味着文档不完整，必须人工补充

- 删除违规内容可能导致文档结构破坏，需人工决策

**例外**：可建议执行以下操作（不自动执行）：

1. 将内容过短且无实际信息的文档移动到 `drafts/` 草稿目录
2. 删除无内容的空章节（需确认该章节确实不需要）
3. 把含 `TODO` 的文档标记为草稿，禁止提交到主分支
