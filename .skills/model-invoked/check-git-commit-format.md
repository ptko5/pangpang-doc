## 检查规则

### R1: 提交信息必须包含完整三段结构（强制）

标准格式：
```
<类型>(<模块>): <简短描述>

<详细描述（可选，空行分隔）>

<关联信息（可选）>
```

**正则校验（首行必填）**：
```regex
^(feat|fix|refactor|docs|style|test|chore|perf|revert)\([^)]+\): .{1,80}$
```

拆解：
- 位置 1（类型）：必须是下表之一
- 位置 2（模块）：`(模块名)`，括号不能省，模块名不能为空
- 位置 3（冒号+空格）：`)` 之后紧跟 `:` 和 **一个空格**
- 位置 4（简短描述）：1~80 个字符，不以句号结尾

### R2: 提交类型必须来自标准枚举（强制）

| 类型 | 说明 | 本项目使用频率 |
|------|------|--------------|
| `feat` | 新功能（文档库中：新增完整文档模块） | 低 |
| `fix` | Bug修复（文档库中：修正文档错误/格式问题） | 中 |
| `refactor` | 重构（文档库中：大幅调整文档结构） | 中 |
| `docs` | 文档变更（**本项目 99% 的提交类型**） | 最高 |
| `style` | 格式调整（纯排版/空格/换行，不改变内容含义） | 中 |
| `test` | 测试相关（文档库中少用） | 极低 |
| `chore` | 杂项（构建脚本/配置/依赖/目录生成器脚本） | 中 |
| `perf` | 性能优化（文档库中：压缩图片、优化脚本性能等） | 低 |
| `revert` | 回滚提交 | 低 |

### R3: 模块名需符合项目约定（强制）

本项目模块名必须是下表之一（或从路径自动推断的更细模块）：

| 模块名 | 对应变更范围 |
|--------|------------|
| `规范` | `docs/00-开发规范/` 下的文档（通用） |
| `规范-前端` / `规范-后端` | 前端/后端开发规范子目录 |
| `环境` | `docs/01-环境搭建/` |
| `运维` | `docs/02-部署运维/` |
| `架构设计` | `docs/03-技术笔记/架构设计/` |
| `源码` | `docs/03-技术笔记/源码阅读/` |
| `排查` | `docs/03-技术笔记/问题排查/` |
| `调研` | `docs/03-技术笔记/新技术调研/` |
| `模板` | `docs/04-项目模板/` |
| `知识` | `docs/05-知识管理/` |
| `总览` | `docs/README.md`、根 `README.md` |
| `脚本` | `scripts/`、`.skills/` 配置变更 |
| `技能体系` | `.skills/` 下的 Skill 定义变更 |

**多模块提交**：用 `/` 分隔，如 `调研/架构设计`。

### R4: 简短描述长度（强制）

首行 `类型(模块): 描述` 中，描述部分：
- **最小长度**：≥ 4 个中文字符或 8 个英文字符（禁止 "update" 等无意义描述）
- **最大长度**：≤ 50 个中文字符或 80 个英文字符（终端显示不换行）
- 描述 **不得以句号结尾**
- 描述建议以动词开头：新增、修复、优化、补充、更新、调整、删除

### R5: 单次提交只包含一个逻辑单元（强制，仅能建议）

通过分析 `git diff --name-only` 的文件列表：
- 如果同时包含 `docs/00-开发规范/` 和 `docs/03-技术笔记/架构设计/` 两个无关联目录
- 且文件数超过 3 个

则输出 **警告**（违规但不阻塞）：建议拆分为多个提交。

## 自动修复逻辑

### R1 / R2 / R3 / R4 组合自动修复

**修复场景**：用户输入了不规范的提交信息，如：
```
新增了国际化文档
修改文档
docs: 更新规范
```

**自动修复算法**：
1. 检查 git 本次暂存的变更文件列表（`git diff --cached --name-only`）
2. 根据文件路径推断：
   - **类型**：如果变更的是 `.md` 文档 → `docs`；如果是 `.py/.sh` 脚本 → `chore`
   - **模块**：按 R3 的映射表从路径推断
3. 提取用户原始描述中的关键词，规范化：
   - 去除句号结尾
   - 超过长度截断（加 `...`）
   - 短于最小长度则补路径关键词（如「更新国际化方案选型文档」）
4. 组合为规范格式

**修复示例**：
```
输入：新增了国际化文档
文件：docs/03-技术笔记/新技术调研/国际化方案选型.md
→ 修复：docs(调研): 新增国际化方案选型文档
```
