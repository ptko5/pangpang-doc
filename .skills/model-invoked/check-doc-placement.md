## 检查规则

### R1: 文档必须位于 docs/ 下的 6 大类目录之一（强制）

**允许的父目录正则**：

```
^docs/(00-开发规范|01-环境搭建|02-部署运维|03-技术笔记|04-项目模板|05-知识管理)/
```

**违规场景**：

- `docs/直接文档.md`（直接挂在 docs 根下，未分类）❌

- `docs/临时目录/xxx.md`（不在 6 大类内）❌

- `docs/00-开发规范.md`（文件命名带编号，未入目录）❌

### R2: 03-技术笔记下必须有二级子目录（强制）

03-技术笔记下不允许直接放 `.md` 文件，必须再细分为：

```
03-技术笔记/
├── 架构设计/          ← 只放架构方案类
├── 源码阅读/          ← 只放源码分析类
├── 问题排查/          ← 只放故障排查类
└── 新技术调研/        ← 只放调研选选型类
```

违规：`docs/03-技术笔记/直接放的文档.md` ❌

### R3: 文档内容与目录语义匹配（强制，基于关键词判定）

基于文档标题和首屏 500 字内容进行分类判定，如果分类置信度 > 阈值但与当前目录不匹配，则判定违规。

**各目录关键词特征**：

| 目标目录               | 关键词（任一命中 + 关键词权重）                                            |
| ------------------ | ------------------------------------------------------------ |
| **00-开发规范/**       | 规范、标准、编码、命名、CR/审查、流程、团队、测试、安全、Git工作流                         |
| **01-环境搭建/**       | 安装、配置、环境、搭建、部署中间件、JDK/Node/IDE、MySQL/Redis/Nginx/ES/MQ 安装    |
| **02-部署运维/**       | 运维、Docker、K8s/Kubernetes、Helm、CI/CD、Jenkins、流水线、服务器、监控、日志、发布 |
| **03-技术笔记/架构设计/**  | 架构设计、系统设计、微服务、分库分表、高并发、缓存、一致性、i18n/国际化、模块拆分                  |
| **03-技术笔记/新技术调研/** | 调研、选型、对比、框架、技术趋势、方案评估、优缺点、mattpocock、i18n方案                  |
| **03-技术笔记/问题排查/**  | 故障、排查、调优、性能优化、线上问题、JVM、根因分析、Bug修复、OOM、死锁                     |
| **03-技术笔记/源码阅读/**  | 源码分析、源码阅读、Spring源码、框架源码、设计模式、类加载、IOC/AOP 实现                  |
| **04-项目模板/**       | 模板、template、骨架、示例模板、README模板、API模板、方案模板、DB设计模板               |
| **05-知识管理/**       | 学习、方法、工具、推荐、书籍、资源、高效、效率、成长、书单                                |

**判定算法**（简化版）：

1. 抽取：`标题 + 一级/二级标题文本 + 首屏 500 字` = 特征文本
2. 对每个目录计算关键词命中数（加权）
3. 取 Top 1 = 预测目录
4. 如果预测目录 ≠ 实际目录 → 违规（给出置信度和建议移动路径）

### R4: 项目模板目录只能放模板类文档（强制）

`04-项目模板/` 下的文档文件名必须包含「模板」字样，或文档标题包含「模板」。

违规示例：

- `04-项目模板/某个实际方案.md`（应该放到 03-技术笔记/架构设计）❌

## 自动修复逻辑

**can-autofix = false**

原因：文档目录归属涉及语义判断，自动移动文件可能破坏用户的刻意安排。仅给出建议，由用户确认后执行。

建议输出格式：

```
⚠️  目录归属不匹配建议：

📄 当前路径：docs/03-技术笔记/架构设计/i18n落地方案.md
🎯 建议移动：docs/03-技术笔记/新技术调研/国际化方案选型.md
📊 判定置信度：87%
🔑 匹配关键词：调研(+30)、对比(+25)、优缺点(+20)、选型(+12)

是否执行移动？[Y/n]
```
