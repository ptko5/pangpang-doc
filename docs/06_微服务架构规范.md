## 2. 微服务设计原则

### 2.1 单一职责原则

#### 【强制】服务边界划分

- 每个微服务只负责 **一个业务能力**
- 服务边界基于 **业务领域** 划分
- 避免服务间的 **强耦合**

#### ✅ 正确示例

```
user-service      # 用户服务（用户管理、认证授权）
order-service     # 订单服务（订单创建、支付、发货）
product-service   # 商品服务（商品管理、库存）
pay-service       # 支付服务（支付处理、退款）
```

#### ❌ 错误示例

```
monolith-service  # 单体服务（包含所有业务逻辑）
```

### 2.2 高内聚低耦合原则

#### 【强制】服务间通信规范

| 通信方式 | 适用场景 | 说明 |
|---------|---------|------|
| **同步调用** | 请求响应模式 | REST API、gRPC |
| **异步消息** | 事件驱动模式 | Kafka、RabbitMQ |
| **本地调用** | 同服务内 | 直接方法调用 |

### 2.3 无状态原则

#### 【强制】服务无状态设计

- 服务本身不存储状态
- 状态存储在 **外部存储**（数据库、缓存）
- 支持 **水平扩展**

## 3. 服务治理规范

### 3.1 服务注册与发现

#### 【强制】服务注册规范

| 组件 | 说明 | 示例 |
|------|------|------|
| **注册中心** | Nacos / Consul / Eureka | Nacos 2.x |
| **服务名** | `{业务}-{模块}-service` | `user-service` |
| **服务分组** | 按环境分组 | `dev`、`test`、`prod` |

#### ✅ 正确示例

```yaml
server:
  port: 8080

spring:
  application:
    name: user-service

nacos:
  discovery:
    server-addr: nacos.example.com:8848
    group: dev
```

### 3.2 配置管理

#### 【强制】配置中心规范

| 组件 | 说明 |
|------|------|
| **配置中心** | Nacos / Apollo / Spring Cloud Config |
| **配置命名** | `{服务名}-{环境}.yaml` |
| **配置分层** | 公共配置 + 服务配置 + 环境配置 |

#### ✅ 正确示例

```yaml

  port: 8080

    url: jdbc:mysql://mysql-dev.example.com:3306/user_db
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}

  level:
    com.example.user: DEBUG
```

### 3.3 负载均衡

#### 【强制】负载均衡规范

| 组件 | 说明 | 策略 |
|------|------|------|
| **客户端负载均衡** | Ribbon / Spring Cloud LoadBalancer | 轮询、随机、权重 |
| **服务端负载均衡** | Nginx / Gateway | 轮询、最小连接数 |

#### ✅ 正确示例

```java
@Configuration
public class LoadBalancerConfig {
    @Bean
    public LoadBalancerClient loadBalancerClient() {
        return new LoadBalancerClientBuilder()
                .withRetryOnAllOperations(true)
                .build();
    }
}
```

### 3.4 熔断降级

#### 【强制】熔断降级规范

| 组件 | 说明 |
|------|------|
| **熔断器** | Sentinel / Hystrix |
| **熔断策略** | 慢调用比例、异常比例、异常数 |
| **降级策略** | 返回默认值、缓存数据、熔断 |

#### ✅ 正确示例

```java
@Service
public class OrderService {
    @SentinelResource(value = "getOrder", fallback = "getOrderFallback")
    public OrderDTO getOrder(Long orderId) {
        return orderClient.getOrder(orderId);
    }

    public OrderDTO getOrderFallback(Long orderId, Throwable e) {
        log.warn("Order service fallback, orderId: {}", orderId, e);
        return new OrderDTO();
    }
}
```

## 4. 服务间通信规范

### 4.1 同步通信

#### 【强制】RESTful调用规范

```java
@FeignClient(name = "order-service", fallback = OrderClientFallback.class)
public interface OrderClient {
    @GetMapping("/api/v1/orders/{id}")
    ApiResponse<OrderDTO> getOrder(@PathVariable("id") Long id);

    @GetMapping("/api/v1/orders")
    ApiResponse<PageResult<OrderDTO>> listOrders(
        @RequestParam("userId") Long userId,
        @RequestParam("page") Integer page,
        @RequestParam("size") Integer size
    );
}

@Component
public class OrderClientFallback implements OrderClient {
    @Override
    public ApiResponse<OrderDTO> getOrder(Long id) {
        return ApiResponse.fail(500, "Order service unavailable");
    }

    @Override
    public ApiResponse<PageResult<OrderDTO>> listOrders(Long userId, Integer page, Integer size) {
        return ApiResponse.fail(500, "Order service unavailable");
    }
}
```

#### 【推荐】gRPC调用规范

```proto
syntax = "proto3";

package user;

option java_multiple_files = true;
option java_package = "com.example.user.grpc";

service UserService {
    rpc GetUser(GetUserRequest) returns (GetUserResponse);
    rpc ListUsers(ListUsersRequest) returns (ListUsersResponse);
}

message GetUserRequest {
    int64 user_id = 1;
}

message GetUserResponse {
    User user = 1;
}

message User {
    int64 id = 1;
    string username = 2;
    string email = 3;
}

message ListUsersRequest {
    int32 page = 1;
    int32 size = 2;
}

message ListUsersResponse {
    repeated User users = 1;
    int64 total = 2;
}
```

### 4.2 异步通信

#### 【强制】消息队列规范

| 组件 | 说明 | 适用场景 |
|------|------|---------|
| **Kafka** | 高吞吐量、持久化 | 日志、事件流 |
| **RabbitMQ** | 可靠性、灵活路由 | 事务消息、延迟队列 |

#### ✅ 正确示例

```java
@Component
public class OrderEventProducer {
    @Autowired
    private KafkaTemplate<String, OrderEvent> kafkaTemplate;

    public void sendOrderCreatedEvent(OrderDTO order) {
        OrderEvent event = new OrderEvent();
        event.setEventType("ORDER_CREATED");
        event.setOrderId(order.getId());
        event.setPayload(order);
        kafkaTemplate.send("order-events", event);
    }
}

@Component
public class OrderEventListener {
    @KafkaListener(topics = "order-events", groupId = "user-group")
    public void handleOrderEvent(ConsumerRecord<String, OrderEvent> record) {
        OrderEvent event = record.value();
        switch (event.getEventType()) {
            case "ORDER_CREATED":
                handleOrderCreated(event);
                break;
            case "ORDER_PAID":
                handleOrderPaid(event);
                break;
        }
    }
}
```

## 5. 分布式事务规范

### 5.1 事务模式选择

#### 【推荐】分布式事务策略

| 模式 | 适用场景 | 实现方式 |
|------|---------|---------|
| **2PC** | 强一致性、短事务 | Seata AT模式 |
| **TCC** | 长事务、业务复杂 | Seata TCC模式 |
| **Saga** | 最终一致性、业务流程 | Seata Saga模式 |
| **本地消息表** | 最终一致性、简单场景 | RocketMQ事务消息 |

#### ✅ 正确示例

```java
@GlobalTransactional(rollbackFor = Exception.class)
public void createOrder(CreateOrderDTO dto) {
    orderService.createOrder(dto);
    inventoryService.decreaseStock(dto.getProductId(), dto.getQuantity());
    payService.createPayment(dto);
}
```

### 5.2 事务回滚策略

#### 【强制】事务回滚规范

| 场景 | 策略 |
|------|------|
| **业务异常** | 抛出异常触发回滚 |
| **网络超时** | 设置合理超时时间 |
| **资源锁定** | 使用分布式锁 |
| **幂等性** | 使用唯一ID去重 |

## 6. API网关规范

### 6.1 网关组件

#### 【强制】网关配置

| 组件 | 说明 |
|------|------|
| **网关** | Spring Cloud Gateway / Zuul |
| **路由规则** | 基于路径匹配 |
| **过滤器** | 鉴权、限流、日志 |

#### ✅ 正确示例

```yaml
server:
  port: 8080

spring:
  cloud:
    gateway:
      routes:
        - id: user-service
          uri: lb://user-service
          predicates:
            - Path=/api/v1/users/**
          filters:
            - StripPrefix=2
            - AuthFilter
            - RateLimitFilter

        - id: order-service
          uri: lb://order-service
          predicates:
            - Path=/api/v1/orders/**
          filters:
            - StripPrefix=2
            - AuthFilter
```

### 6.2 网关过滤器

#### 【推荐】过滤器链

| 过滤器 | 说明 | 执行顺序 |
|--------|------|---------|
| **AuthFilter** | 认证鉴权 | 1 |
| **RateLimitFilter** | 限流 | 2 |
| **LogFilter** | 日志记录 | 3 |
| **TraceFilter** | 链路追踪 | 4 |
| **StripPrefixFilter** | 路径处理 | 5 |

## 9. 服务部署规范

#### 【强制】Docker部署规范

```dockerfile
FROM openjdk:25-jdk-slim

COPY target/user-service.jar app.jar
```

### 9.2 Kubernetes部署

#### 【推荐】K8s配置规范

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: user-service
  labels:
    app: user-service

  replicas: 3
  selector:
    matchLabels:
      app: user-service
  template:
    metadata:
      labels:
        app: user-service
    spec:
      containers:
        - name: user-service
          image: registry.example.com/user-service:latest
          ports:
            - containerPort: 8080
          resources:
```
