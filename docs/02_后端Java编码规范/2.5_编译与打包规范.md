## 2. JDK25编译配置

#### 【强制】pom.xml JDK25配置

```xml
<?xml version="1.0" encoding="UTF-8"?>

        <groupId>org.springframework.boot</groupId>
```

```groovy

    testImplementation 'org.springframework.boot:spring-boot-starter-test'

    useJUnitPlatform()
}
```

### 2.3 工具链配置

#### 【推荐】Maven Toolchains配置

在 `~/.m2/toolchains.xml` 中配置：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<toolchains>
    <toolchain>
        <type>jdk</type>
        <provides>
            <version>25</version>
            <vendor>openjdk</vendor>
        </provides>
        <configuration>
            <jdkHome>/path/to/jdk25</jdkHome>
        </configuration>
    </toolchain>
</toolchains>
```

在pom.xml中启用工具链：

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-toolchains-plugin</artifactId>
    <version>3.1.0</version>
    <executions>
        <execution>
            <goals>
                <goal>toolchain</goal>
            </goals>
        </execution>
    </executions>
    <configuration>
        <toolchains>
            <jdk>
                <version>25</version>
            </jdk>
        </toolchains>
    </configuration>
</plugin>
```

## 3. 模块化配置

### 3.1 module-info.java

#### 【强制】模块声明

```java
module com.example.user {
    requires spring.context;
    requires spring.web;
    requires spring.data.jpa;
    requires com.example.common;
    requires jakarta.persistence;
    requires lombok;
    requires org.slf4j;
    
    exports com.example.user.controller;
    exports com.example.user.dto;
    exports com.example.user.vo;
    
    opens com.example.user.entity to spring.orm, spring.beans;
    opens com.example.user.dto to spring.core;
    opens com.example.user.vo to spring.core;
}
```

#### 【推荐】模块依赖管理

| 指令 | 说明 | 示例 |
|------|------|------|
| `requires` | 声明依赖其他模块 | `requires spring.context;` |
| `requires transitive` | 传递依赖 | `requires transitive com.example.common;` |
| `exports` | 导出包 | `exports com.example.user.controller;` |
| `exports ... to` | 定向导出 | `exports com.example.user.internal to com.example.admin;` |
| `opens` | 开放包（反射访问） | `opens com.example.user.entity to spring.orm;` |
| `provides` / `uses` | 服务提供/消费 | `provides DataSource with HikariDataSource;` |

## 4. 打包规范

### 4.1 Maven打包配置

#### 【强制】Spring Boot打包

```xml
<build>
    <plugins>
        <plugin>

            <version>3.2.0</version>
            <executions>
                <execution>
                    <goals>

                    </goals>

                    </include>
                </includes>

    </plugins>
```

### 4.2 Jar包命名规范

#### 【强制】Jar包命名

```
{artifactId}-{version}-{env}.jar
```

示例：
- `user-service-1.0.0.jar` - 默认打包
- `user-service-1.0.0-SNAPSHOT.jar` - 快照版本
- `user-service-1.0.0-prod.jar` - 生产环境

#### 【推荐】构建命令

```bash
# 编译
mvn compile

# 运行测试
mvn test

# 打包（跳过测试）
mvn package -DskipTests

# 打包（含测试）
mvn package

# 清理并打包
mvn clean package

# 安装到本地仓库
mvn install

# 部署到远程仓库
mvn deploy
```

## 5. Docker镜像规范

### 5.1 Dockerfile

#### 【强制】Dockerfile模板

```dockerfile
FROM eclipse-temurin:25-jre-alpine

WORKDIR /app

COPY target/*.jar app.jar

ENV JAVA_OPTS="-Xms256m -Xmx512m -XX:+UseG1GC -XX:+EnableJVMCI"

EXPOSE 8080

ENTRYPOINT ["java", "-jar", "app.jar"]
```

#### 【推荐】多阶段构建

```dockerfile
FROM eclipse-temurin:25-jdk-alpine AS builder

WORKDIR /app

COPY pom.xml .
COPY src ./src

RUN mvn clean package -DskipTests

FROM eclipse-temurin:25-jre-alpine

WORKDIR /app

COPY --from=builder /app/target/*.jar app.jar

ENV JAVA_OPTS="-Xms256m -Xmx512m"

EXPOSE 8080

ENTRYPOINT ["java", "-jar", "app.jar"]
```

#### 【强制】Docker镜像命名规范

```
{registry}/{namespace}/{service-name}:{version}-{build-number}
```

示例：
- `registry.example.com/example/user-service:1.0.0-123`

## 7. 构建脚本规范

### 7.1 启动脚本

#### 【强制】start.sh

```bash
#!/bin/bash

APP_NAME="user-service"
APP_JAR="target/${APP_NAME}-1.0.0.jar"
LOG_FILE="logs/${APP_NAME}.log"

mkdir -p logs

echo "Starting ${APP_NAME}..."

nohup java -jar ${APP_JAR} \
    --spring.profiles.active=prod \
    --server.port=8080 \
    > ${LOG_FILE} 2>&1 &

echo "${APP_NAME} started with PID: $!"
```

#### 【强制】stop.sh

```bash
#!/bin/bash

APP_NAME="user-service"

PID=$(ps -ef | grep ${APP_NAME} | grep -v grep | awk '{print $2}')

if [ -z "${PID}" ]; then
    echo "${APP_NAME} is not running"
    exit 1
fi

echo "Stopping ${APP_NAME} (PID: ${PID})..."

kill ${PID}

sleep 3

PID=$(ps -ef | grep ${APP_NAME} | grep -v grep | awk '{print $2}')

if [ -z "${PID}" ]; then
    echo "${APP_NAME} stopped successfully"
else
    echo "Force killing ${APP_NAME} (PID: ${PID})..."
    kill -9 ${PID}
    echo "${APP_NAME} force stopped"
fi
```

### 7.2 健康检查脚本

#### 【推荐】health.sh

```bash
#!/bin/bash

URL="http://localhost:8080/actuator/health"
TIMEOUT=5

response=$(curl -s -o /dev/null -w "%{http_code}" --max-time ${TIMEOUT} ${URL})

if [ "${response}" == "200" ]; then
    echo "Service is healthy"
    exit 0
else
    echo "Service is unhealthy (HTTP ${response})"
    exit 1
fi
```
