## 2. 命名规范

### 2.1 包命名

#### 【强制】包名规则

- 包名全部使用 **小写英文**
- 使用 **公司域名倒序** 作为顶级包名
- 层级结构：`com.company.business.module`
- 禁止使用下划线、数字开头

#### ✅ 正确示例

```java
com.example.user.controller
com.example.order.service
com.example.common.util
```

#### ❌ 错误示例

```java
com.Example.User        // 错误：使用大写
com/example/user        // 错误：使用斜杠
com.company_abc.user    // 错误：使用下划线
```

### 2.2 类命名

#### 【强制】类名规则

- 类名使用 **大驼峰（PascalCase）**
- 类名必须 **见名知意**，使用完整英文单词
- 禁止使用缩写（除非是广为人知的缩写如 `DTO`、`VO`、`PO`）

#### 【强制】类名后缀

| 类类型 | 后缀 | 示例 |
|-------|------|------|
| 控制器 | `Controller` | `UserController` |
| 服务接口 | `Service` | `UserService` |
| 服务实现 | `ServiceImpl` | `UserServiceImpl` |
| 数据访问层 | `Mapper` | `UserMapper` |
| 实体类 | `PO` | `UserPO` |
| 数据传输对象 | `DTO` | `UserDTO` |
| 视图对象 | `VO` | `UserVO` |
| 配置类 | `Config` | `WebConfig` |
| 异常类 | `Exception` | `BusinessException` |
| 枚举类 | `Enum` | `UserStatusEnum` |
| 工具类 | `Utils` | `DateUtils` |

#### ✅ 正确示例

```java
public class UserController { }
public interface UserService { }
public class UserServiceImpl implements UserService { }
public interface UserMapper { }
public class UserPO { }
public class CreateUserDTO { }
public class UserVO { }
public class WebMvcConfig { }
public class BusinessException extends RuntimeException { }
public enum UserStatusEnum { }
public final class DateUtils { }
```

#### ❌ 错误示例

```java
public class UserCtrl { }           // 错误：使用缩写
public class UserServ { }           // 错误：使用缩写
public class userPO { }             // 错误：使用小驼峰
public class USER_PO { }            // 错误：使用全大写加下划线
public class UserDao { }            // 错误：使用Dao，应使用Mapper
```

### 2.3 方法命名

#### 【强制】方法名规则

- 方法名使用 **小驼峰（camelCase）**
- 方法名必须 **见名知意**，使用动词开头
- 禁止使用下划线、数字开头

#### 【推荐】方法命名模式

| 操作类型 | 前缀 | 示例 |
|---------|------|------|
| 查询单个 | `get` / `find` | `getUserById`, `findUserByName` |
| 查询列表 | `list` / `query` | `listUsers`, `queryUsersByStatus` |
| 新增 | `create` / `add` | `createUser`, `addOrder` |
| 更新 | `update` | `updateUser` |
| 删除 | `delete` / `remove` | `deleteUser`, `removeOrder` |
| 批量操作 | `batch` + 操作 | `batchCreateUsers`, `batchDelete` |
| 统计 | `count` | `countUsers` |
| 检查 | `exists` / `check` | `existsByEmail`, `checkPermission` |

#### ✅ 正确示例

```java
public UserVO getUserById(Long id) { }
public List<UserVO> listUsers(UserQueryDTO query) { }
public Long createUser(CreateUserDTO dto) { }
public void updateUser(Long id, UpdateUserDTO dto) { }
public void deleteUser(Long id) { }
public boolean existsByEmail(String email) { }
```

#### ❌ 错误示例

```java
public UserVO getUser(Long id) { }           // 错误：getUser语义不明确
public void save(UserPO user) { }            // 错误：save语义不明确（新增还是更新？）
public void del(Long id) { }                 // 错误：使用缩写
public void UpdateUser(Long id) { }          // 错误：首字母大写
```

### 2.4 变量命名

#### 【强制】变量名规则

- 变量名使用 **小驼峰（camelCase）**
- 变量名必须 **见名知意**，避免使用 `a`、`b`、`temp` 等无意义变量
- 禁止使用下划线、数字开头

#### 【强制】特殊变量命名

| 变量类型 | 规则 | 示例 |
|---------|------|------|
| 常量 | 全大写 + 下划线分隔 | `MAX_PAGE_SIZE`, `DEFAULT_TIMEOUT` |
| 集合 | 使用复数形式 | `users`, `orders`, `userList` |
| 布尔变量 | 使用 `is` / `has` / `can` / `should` 前缀 | `isActive`, `hasPermission`, `canDelete` |

#### ✅ 正确示例

```java
public static final int MAX_PAGE_SIZE = 100;
public static final String DEFAULT_PASSWORD = "123456";

List<UserVO> users = userService.listUsers(query);
boolean isActive = user.getStatus() == UserStatusEnum.ACTIVE;
boolean hasPermission = permissionService.checkPermission(userId, resourceId);
```

#### ❌ 错误示例

```java
public static final int maxPageSize = 100;     // 错误：常量使用小驼峰
public static final String DefaultPassword = "123456";  // 错误：常量使用大驼峰

List<UserVO> userListData = userService.listUsers(query);  // 错误：冗余后缀
boolean active = user.getStatus() == UserStatusEnum.ACTIVE;  // 错误：缺少is前缀
```

### 2.5 接口命名

#### 【强制】接口命名规则

- 接口名使用 **大驼峰（PascalCase）**
- 接口名使用 **名词**，表示"能力"或"服务"
- 禁止在接口名前加 `I` 前缀

#### ✅ 正确示例

```java
public interface UserService { }
public interface OrderRepository { }
public interface MessageProducer { }
```

#### ❌ 错误示例

```java
public interface IUserService { }    // 错误：使用I前缀
public interface IUser { }           // 错误：使用I前缀
```

## 3. 注释规范

### 3.1 文件头部注释

#### 【强制】文件头部注释

所有Java源文件必须包含文件头部注释，格式如下：

```java
/**
 * 文件说明: 用户控制器
 * 
 * @author 张三
 * @date 2026-06-30
 * @version 1.0.0
 */
package com.example.user.controller;

import org.springframework.web.bind.annotation.RestController;

@RestController
public class UserController {
    // ...
}
```

### 3.2 类注释

#### 【强制】类注释

所有类必须包含类注释，说明类的功能和职责：

```java
/**
 * 用户服务接口
 * 
 * 提供用户的增删改查、权限验证等功能
 */
public interface UserService {
    // ...
}
```

### 3.3 方法注释

#### 【强制】方法注释

所有公共方法（`public`）必须包含方法注释，格式如下：

```java
/**
 * 根据用户ID查询用户信息
 * 
 * @param id 用户ID
 * @return 用户视图对象
 * @throws BusinessException 当用户不存在时抛出
 */
public UserVO getUserById(Long id) {
    // ...
}
```

#### 【强制】方法注释必须包含的标签

| 标签 | 说明 | 必填 |
|------|------|------|
| `@param` | 参数说明，每个参数一个 | 是 |
| `@return` | 返回值说明 | 是（无返回值时省略） |
| `@throws` | 抛出的异常说明 | 是（有异常时） |

#### ✅ 正确示例

```java
/**
 * 创建用户
 * 
 * @param dto 用户创建请求DTO
 * @return 创建成功的用户ID
 * @throws BusinessException 当邮箱已存在时抛出
 * @throws ValidationException 当参数校验失败时抛出
 */
public Long createUser(CreateUserDTO dto) {
    // ...
}

/**
 * 删除用户
 * 
 * @param id 用户ID
 * @throws BusinessException 当用户不存在时抛出
 */
public void deleteUser(Long id) {
    // ...
}
```

### 3.4 代码注释

#### 【推荐】代码注释规则

- **简洁明了**：注释应说明"为什么"而非"做什么"，代码本身应能表达"做什么"
- **避免冗余**：不要注释显而易见的代码
- **及时更新**：代码修改时同步更新注释

#### ✅ 正确示例

```java
// 使用虚拟线程处理IO密集型任务，提升吞吐量
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    executor.submit(this::processFileUpload);
}

// 由于历史原因，用户状态使用0/1表示，这里做兼容处理
if (user.getStatus() == 0) {
    user.setStatus(UserStatusEnum.INACTIVE);
}
```

#### ❌ 错误示例

```java
// 获取用户列表
List<UserVO> users = userService.listUsers();  // 冗余注释

// 循环遍历用户
for (UserVO user : users) {                    // 冗余注释
    // 打印用户名
    System.out.println(user.getName());        // 冗余注释
}
```

## 4. 分层规范

### 4.1 架构分层

#### 【强制】分层架构

后端采用 **经典三层架构** + **数据访问层**：

```
┌─────────────────────────────────────────────────────────────┐
│                        Controller层                         │
│  负责接收HTTP请求、参数校验、调用Service、返回响应            │
├─────────────────────────────────────────────────────────────┤
│                         Service层                           │
│  负责业务逻辑处理、事务管理、调用Mapper                       │
├─────────────────────────────────────────────────────────────┤
│                         Mapper层                            │
│  负责数据库访问、SQL执行                                     │
├─────────────────────────────────────────────────────────────┤
│                         PO层                                │
│  数据库表映射的实体类                                        │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 数据对象定义

#### 【强制】数据对象分层

| 对象类型 | 全称 | 用途 | 所属包 |
|---------|------|------|--------|
| **PO** | Persistent Object | 数据库表映射，与表结构一一对应 | `entity` / `po` |
| **DTO** | Data Transfer Object | 数据传输对象，用于接口请求/响应 | `dto` |
| **VO** | View Object | 视图对象，用于前端展示 | `vo` |
| **BO** | Business Object | 业务对象，用于业务逻辑处理 | `bo` |

#### 【强制】数据对象命名规则

| 对象类型 | 命名规则 | 示例 |
|---------|---------|------|
| PO | 表名 + `PO` | `user` → `UserPO` |
| 请求DTO | 操作 + 实体 + `DTO` | `CreateUserDTO`, `UpdateUserDTO`, `UserQueryDTO` |
| 响应DTO | 实体 + `VO` | `UserVO`, `OrderVO` |
| BO | 业务 + `BO` | `UserAuthBO`, `OrderProcessBO` |

#### ✅ 正确示例

```java
// PO - 与数据库表一一对应
public class UserPO {
    private Long id;
    private String username;
    private String email;
    private String password;
    private Integer status;
    private LocalDateTime createdAt;
    private LocalDateTime updatedAt;
    // getter/setter
}

// 请求DTO - 创建用户
public class CreateUserDTO {
    @NotBlank(message = "用户名不能为空")
    private String username;
    
    @NotBlank(message = "邮箱不能为空")
    @Email(message = "邮箱格式不正确")
    private String email;
    
    @NotBlank(message = "密码不能为空")
    @Size(min = 6, max = 20, message = "密码长度必须在6-20之间")
    private String password;
    // getter/setter
}

// 响应VO - 用户信息
public class UserVO {
    private Long id;
    private String username;
    private String email;
    private UserStatusEnum status;
    private LocalDateTime createdAt;
    // getter/setter
}
```

### 4.3 分层职责边界

#### 【强制】分层职责

| 层级 | 职责 | 禁止操作 |
|------|------|---------|
| **Controller** | 接收请求、参数校验、调用Service、返回响应 | 直接操作数据库、复杂业务逻辑 |
| **Service** | 业务逻辑处理、事务管理、调用Mapper | 直接接收HTTP请求、处理HTTP响应 |
| **Mapper** | 数据库访问、SQL执行 | 业务逻辑处理、事务管理 |
| **PO** | 数据映射 | 业务逻辑、参数校验 |

#### ✅ 正确示例

```java
// Controller层
@RestController
@RequestMapping("/api/users")
public class UserController {
    
    @Autowired
    private UserService userService;
    
    @GetMapping("/{id}")
    public ApiResponse<UserVO> getUserById(@PathVariable Long id) {
        UserVO user = userService.getUserById(id);
        return ApiResponse.success(user);
    }
}

// Service层
@Service
@Transactional
public class UserServiceImpl implements UserService {
    
    @Autowired
    private UserMapper userMapper;
    
    @Override
    public UserVO getUserById(Long id) {
        UserPO userPO = userMapper.selectById(id);
        if (userPO == null) {
            throw new BusinessException("用户不存在");
        }
        return UserConverter.toVO(userPO);
    }
}

// Mapper层
@Mapper
public interface UserMapper {
    UserPO selectById(Long id);
}
```

## 5. 代码格式规范

### 5.1 缩进

#### 【强制】缩进规则

- 使用 **4个空格** 进行缩进
- 禁止使用 **Tab键** 进行缩进
- IDE必须配置为"Tab替换为空格"

### 5.2 空行

#### 【强制】空行规则

- 类的成员之间（方法、字段）必须有 **1个空行**
- 方法内部逻辑块之间使用 **1个空行** 分隔
- 禁止连续多个空行

#### ✅ 正确示例

```java
public class UserController {
    
    @Autowired
    private UserService userService;
    
    @GetMapping("/{id}")
    public ApiResponse<UserVO> getUserById(@PathVariable Long id) {
        UserVO user = userService.getUserById(id);
        return ApiResponse.success(user);
    }
    
    @PostMapping
    public ApiResponse<Long> createUser(@RequestBody @Valid CreateUserDTO dto) {
        Long userId = userService.createUser(dto);
        return ApiResponse.success(userId);
    }
}
```

### 5.3 大括号

#### 【强制】大括号规则

- 大括号 **不换行**，与前面的代码在同一行
- 大括号内的代码 **缩进1级**
- 单行语句也必须使用大括号（禁止省略）

#### ✅ 正确示例

```java
if (user != null) {
    return user;
}

for (int i = 0; i < 10; i++) {
    System.out.println(i);
}
```

#### ❌ 错误示例

```java
if (user != null) return user;        // 错误：省略大括号
if (user != null)
{                                     // 错误：大括号换行
    return user;
}
```

### 5.4 空格

#### 【强制】空格规则

- 关键字与括号之间 **必须有空格**：`if (condition)`、`for (int i = 0)`
- 运算符两侧 **必须有空格**：`a + b`、`x > 0`
- 逗号后 **必须有空格**：`method(a, b, c)`
- 方法名与括号之间 **禁止有空格**：`method()` 而非 `method ()`

#### ✅ 正确示例

```java
if (age > 18 && hasPermission) {
    return true;
}

for (int i = 0; i < 10; i++) {
    process(i);
}

calculateTotal(price, quantity, discount);
```

## 6. 异常处理规范

### 6.1 异常分类

#### 【强制】异常分类

| 异常类型 | 用途 | 示例 |
|---------|------|------|
| **BusinessException** | 业务异常，由业务逻辑抛出 | 用户不存在、订单已关闭 |
| **ValidationException** | 参数校验异常 | 邮箱格式错误、密码长度不足 |
| **SystemException** | 系统异常，由底层错误抛出 | 数据库连接失败、网络超时 |
| **SecurityException** | 安全异常 | 权限不足、Token过期 |

### 6.2 异常抛出规范

#### 【强制】异常抛出规则

- 业务异常使用 `BusinessException`，携带业务错误码和错误信息
- 参数校验使用 `@Valid` + `ValidationException`
- 禁止直接抛出 `Exception` 或 `RuntimeException`

#### ✅ 正确示例

```java
public UserVO getUserById(Long id) {
    UserPO userPO = userMapper.selectById(id);
    if (userPO == null) {
        throw new BusinessException(ErrorCode.USER_NOT_FOUND, "用户不存在");
    }
    return UserConverter.toVO(userPO);
}
```

#### ❌ 错误示例

```java
public UserVO getUserById(Long id) {
    UserPO userPO = userMapper.selectById(id);
    if (userPO == null) {
        throw new RuntimeException("用户不存在");  // 错误：使用通用异常
    }
    return UserConverter.toVO(userPO);
}
```

### 6.3 异常捕获规范

#### 【强制】异常捕获规则

- 捕获异常时 **必须处理**，禁止空的 `catch` 块
- 禁止捕获 `Exception` 后不做任何处理
- 捕获异常后应记录日志或向上抛出

#### ✅ 正确示例

```java
try {
    userService.createUser(dto);
} catch (BusinessException e) {
    log.warn("创建用户失败: {}", e.getMessage());
    throw e;
} catch (Exception e) {
    log.error("创建用户发生系统错误", e);
    throw new SystemException("系统繁忙，请稍后重试");
}
```

#### ❌ 错误示例

```java
try {
    userService.createUser(dto);
} catch (Exception e) {
    // 错误：空的catch块，吞掉异常
}
```

## 7. 日志规范

### 7.1 日志框架

#### 【强制】日志框架

- 使用 **SLF4J** 作为日志门面
- 使用 **Logback** 作为日志实现
- 禁止直接使用 `System.out.println()` 或 `System.err.println()`

### 7.2 日志级别

#### 【强制】日志级别使用

| 级别 | 用途 | 使用场景 |
|------|------|---------|
| **TRACE** | 最细粒度的日志 | 详细的调试信息，生产环境关闭 |
| **DEBUG** | 调试信息 | 开发阶段使用，生产环境关闭 |
| **INFO** | 一般信息 | 关键业务流程、系统启动信息 |
| **WARN** | 警告信息 | 可恢复的异常、潜在问题 |
| **ERROR** | 错误信息 | 不可恢复的异常、系统错误 |

#### 【强制】日志级别规范

- **生产环境**：只输出 `INFO` 及以上级别日志
- **开发环境**：可输出 `DEBUG` 及以上级别日志
- **禁止**在循环中打印 `DEBUG` 及以下级别的日志

### 7.3 日志输出规范

#### 【强制】日志输出格式

- 使用参数化日志，禁止字符串拼接
- 日志信息应包含 **上下文信息**（用户ID、请求ID、业务ID等）

#### ✅ 正确示例

```java
log.info("用户登录成功, userId={}, ip={}", userId, ipAddress);
log.warn("订单支付超时, orderId={}, timeout={}ms", orderId, timeout);
log.error("创建用户失败, dto={}", dto, e);
```

#### ❌ 错误示例

```java
log.info("用户登录成功, userId=" + userId + ", ip=" + ipAddress);  // 错误：字符串拼接
log.info("用户登录成功");                                            // 错误：缺少上下文信息
```
