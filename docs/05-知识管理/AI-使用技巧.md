## 2. 核心观念：把 AI 当协作者，不当答案机器

- **AI 擅长编排与初稿，判断与验证仍是人的责任**：所有输出必须人工复核后再落地。
- **把 Skill 当纪律，不当框架**：通过固定提示模板与检查清单约束输出质量，而非依赖随机对话。详见 [mattpocock-skills-调研-把Skill当纪律不当框架](../03-技术笔记/新技术调研/mattpocock-skills-调研-把Skill当纪律不当框架.md)。
- **迭代优于一次到位**：先让 AI 给出方案再逐步收敛，而不是期待一句话产出完美结果。

> 【强制】AI 输出未经验证禁止合入生产代码；禁止向 AI 粘贴密钥、Token、生产数据与个人隐私信息。

## 3. 高效提问技巧（提示词）

### 3.1 四要素模板

任何任务描述尽量包含：**角色 + 任务 + 上下文 + 约束**。

```text
[角色] 你是一名资深 Java 后端工程师
[任务] 帮我审查下面这段代码的并发安全性
[上下文] 使用 JDK 25 + Spring Boot 4.x，订单创建接口，QPS 峰值 2000
[约束] 只指出问题与修复建议，不要重写整段代码；输出用中文
```

### 3.2 给足上下文

| 场景 | 需要补充的信息 |
|------|----------------|
| 报错排查 | 完整错误堆栈、复现步骤、相关代码片段、运行环境 |
| 代码生成 | 技术栈版本（JDK 25 / Spring Boot 4.x）、已有代码风格、约束条件 |
| 文档撰写 | 面向读者、篇幅要求、必须包含的章节 |
| 方案评审 | 业务背景、非功能需求（性能/安全/成本）、可选方案 |

### 3.3 拆分任务

一次只让 AI 做一件事。把"帮我写一个订单系统"拆成：

```text
1. 先输出订单模块的数据库表设计（含索引建议）
2. 再生成创建订单的 Service 代码
3. 最后写对应的单元测试
```

### 3.4 明确输出格式

- 要求输出 Markdown / 表格 / 代码块 / Mermaid 图
- 要求「先给结论再给论证」「只列要点不要长篇」
- 要求用指定语言回复，避免中英混杂

## 4. 编程场景技巧

### 4.1 代码生成与重构

```text
把下面的实现改为使用 Spring Cache + Redis，要求：
1. 保留原有方法签名
2. 处理缓存穿透（加空值缓存）与雪崩（TTL 加随机抖动）
3. 给出修改前后的对比说明
```

### 4.2 代码审查

让 AI 当"第一轮 Reviewer"，人做终审，可显著提升审查效率：

```text
按以下清单审查代码：正确性 / 并发安全 / 边界条件 / 性能隐患 /
是否符合团队规范（见 00-开发规范）。逐条列出问题与严重程度。
```

> 人工审查流程见 [代码审查规范](../00-开发规范/代码审查规范.md)。

### 4.3 Bug 定位

```text
我的接口偶发超时，以下是线程栈与 GC 日志，请帮我定位可能原因：
<粘贴线程栈 / 日志>。要求：先给最可能的 3 个原因，再给验证方法。
```

### 4.4 解释与学习

用 AI 做"费曼陪练"，让它用通俗语言解释概念，再让它出题检验理解：

```text
用 8 岁小孩能听懂的话解释 Spring 的依赖注入；
然后给我出 5 道判断题检验我是否真的理解。
```

## 5. 文档编写技巧

### 5.1 起草

```text
基于以下要点，撰写一份《XX 方案设计》文档，遵循
docs/00-开发规范/文档书写规范.md 的结构与排版要求：
1. ... 2. ... 3. ...
```

### 5.2 校对与格式检查

```text
检查这篇文档：标题层级是否跳级、中英文之间是否有空格、
代码块是否标注了语言、是否有占位符（待补充）。
列出违规项与修正建议。
```

### 5.3 总结与复盘

- 让 AI 从会议纪要/故障复盘中提炼"根因→改进项→责任人"
- 让 AI 把长文档压缩成 5 分钟速读版，便于分享

- **生成复习卡片**：让 AI 把一篇技术笔记转成 Anki 问答卡片
- **费曼讲解**：让 AI 扮演"追问者"，用问题逼你把概念讲透
- **路线规划**：让 AI 基于 [高效学习法](./高效学习法.md) 帮你拆解学习路线

## 7. 常见误区与红线

| 误区 | 正确做法 |
|------|---------|
| 盲信输出直接合入 | 人工复核 + 测试验证 |
| 粘贴密钥/生产数据 | 一律脱敏，敏感信息禁止入对话 |
| 需求一句话就期待完美结果 | 用四要素模板 + 迭代追问 |
| 上下文过长/信息过载 | 拆任务、给关键片段而非整库粘贴 |
| 让 AI 编造"事实" | 涉及版本/文档/数据，以官方来源核对 |
