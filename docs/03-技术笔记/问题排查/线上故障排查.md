---

## 2. 故障分级（P0-P3）

| 级别 | 定义 | 响应时限 | 处理 |
|------|------|---------|------|
| **P0** | 核心业务完全不可用/资损 | 立即 | 全员响应，优先恢复 |
| **P1** | 核心功能部分不可用 | 15 分钟 | 值班组长指挥 |
| **P2** | 非核心功能异常 | 4 小时 | 按迭代修复 |
| **P3** | 小缺陷/体验问题 | 下个迭代 | 正常排期 |

> 【强制】P0/P1 必须立即上报并开启故障群，恢复优先于排查，禁止私自发布未验证修复。

## 3. 5 步排查法

```mermaid
flowchart LR
    A[1 快速止血] --> B[2 收集现场]
    B --> C[3 根因定位]
    C --> D[4 修复验证]
    D --> E[5 复盘沉淀]
```

| 步骤 | 动作 |
|------|------|
| **1 快速止血** | 回滚/重启/熔断降级，先恢复可用 |
| **2 收集现场** | 日志、dump、监控、变更记录（时间线） |
| **3 根因定位** | 从「变更、依赖、资源、代码」四维度排查 |
| **4 修复验证** | 灰度验证后全量，确认指标恢复 |
| **5 复盘沉淀** | 输出根因、改进项，防复发 |

## 4. 排查清单

### 4.1 变更维度（最常见根因）

- 最近是否发布/变更配置/升级依赖？
- 变更前后对比（git log / 发布单）

### 4.2 依赖维度

- 下游服务/中间件（MySQL/Redis/MQ）是否正常？
- 依赖调用是否有超时/熔断？

### 4.3 资源维度

- CPU / 内存 / 磁盘 / 连接数是否打满？
- GC、连接池、线程池是否异常？

### 4.4 代码维度

- 异常堆栈、慢日志、特定参数触发？
- 并发/死锁/数据不一致？

```bash
# 现场收集常用命令
tail -100f /var/log/app/error.log
jstack <pid> > thread.dump
jstat -gcutil <pid> 1000
df -h; free -h; top
```

## 5. 常见故障速查表

| 故障现象 | 常见根因 | 快速处置 |
|---------|---------|---------|
| 接口全部超时 | 下游依赖挂/连接池耗尽 | 熔断降级、扩容 |
| CPU 100% | 死循环/GC 异常 | 抓线程栈定位 |
| 内存持续上涨 | 泄漏/缓存无限增长 | dump 分析 |
| 磁盘满 | 日志/数据膨胀 | 清理 + 日志轮转 |
| 数据库锁等待 | 长事务/大事务 | 查 `information_schema` 杀锁 |
| 消息堆积 | 消费慢/异常 | 扩容消费者、排查异常 |
| 缓存雪崩 | 大量 key 同时过期 | 限流 + 重建兜底 |

## 6. 复盘模板

```text
## 故障复盘
### 1. 故障概况
- 时间线、影响范围、级别
### 2. 根因分析
- 直接原因 / 触发条件 / 深层原因
### 3. 处理过程
- 止血动作、时间点、负责人
### 4. 改进措施
- 短期（立即可做）/ 长期（架构级）
### 5. 跟进人
- 负责人与截止时间
```

> 【强制】P0/P1 故障必须 48 小时内完成复盘并归档，改进项闭环跟踪。
