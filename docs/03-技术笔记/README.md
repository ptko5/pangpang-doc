## 4. 技术沉淀规范（写技术笔记前必读）

### 4.1 【强制】沉淀触发时机

| 场景 | 动作 |
|------|------|
| 完成一个系统级架构设计 | 沉淀到 `架构设计/` |
| 线上解决了疑难故障 | 沉淀到 `问题排查/` |
| 深入阅读了某框架源码 | 沉淀到 `源码阅读/` |
| 完成一次技术选型调研 | 沉淀到 `新技术调研/` |
| 解决了可复用的性能问题 | 沉淀到 `问题排查/性能优化案例.md` |

### 4.2 【推荐】笔记质量标准

- **可复用**：别人遇到同类问题能按你的步骤复现与解决
- **可追溯**：记录环境版本、时间、涉及模块，便于回溯
- **有结论**：问题排查必须有根因结论，选型必须有推荐结论，禁止模棱两可
- **引用规范**：涉及规范的内容引用 `../00-开发规范/`，不重复造轮子
