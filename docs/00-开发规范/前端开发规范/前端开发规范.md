## 2. 代码规范

### 2.1 命名规范

| 类型 | 规范 | 示例 |
|-|-|-|
| 组件命名 | PascalCase | `UserProfile`、`OrderList` |
| 变量命名 | camelCase | `userName`、`isLoading` |
| 布尔变量 | is/has/can 前缀 | `isActive`、`hasPermission` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRY_COUNT` |
| 函数命名 | camelCase | `fetchUserData`、`handleClick` |
| 样式类名 | BEM 规范 | `block__element--modifier` |

### 2.2 代码格式

```json
{
  "extends": ["eslint:recommended", "plugin:react/recommended"],
  "rules": {
    "no-console": "warn",
    "no-unused-vars": "error",
    "prefer-const": "error"
  }
}
```

```json
{
  "semi": true,
  "singleQuote": true,
  "tabWidth": 2,
  "trailingComma": "es5"
}
```

- 统一使用 2 空格缩进
- 每行不超过 120 个字符
- 文件末尾保留一个空行

### 2.3 注释规范

```typescript
/**
 * 获取用户信息
 * @param userId - 用户ID
 * @returns 用户信息对象
 */
async function fetchUser(userId: string): Promise<User> {
  // TODO: 添加错误处理
  return api.get(`/users/${userId}`);
}
```

### 2.4 目录结构

```bash
src/
├── components/      # 公共组件
├── pages/           # 页面组件
├── hooks/           # 自定义 Hooks
├── utils/           # 工具函数
├── services/        # API 服务层
├── stores/          # 状态管理
├── types/           # TypeScript 类型定义
├── assets/          # 静态资源
└── styles/          # 全局样式
```

## 3. Git 协作规范

### 3.1 分支命名策略

| 分支类型 | 命名格式 | 示例 |
|-|-|-|
| 功能分支 | feature/功能描述 | feature/user-login |
| 修复分支 | fix/问题描述 | fix/login-timeout |
| 发布分支 | release/版本号 | release/v1.2.0 |
| 热修复分支 | hotfix/问题描述 | hotfix/critical-bug |

### 3.2 Commit Message 规范

采用 Angular 规范格式：`<type>(<scope>): <subject>`

| Type | 说明 |
|-|-|
| feat | 新功能 |
| fix | Bug 修复 |
| docs | 文档更新 |
| style | 格式调整 |
| refactor | 重构 |
| test | 测试相关 |
| chore | 构建/工具变动 |

### 3.3 Code Review 注意事项

- PR 描述必须包含：改动内容、关联需求、测试结果
- 每次 Review 聚焦于少量改动
- Reviewer 必须验证功能正确性和代码质量
- 至少 1 人 Approve 方可合并

## 4. 组件开发规范

### 4.1 组件设计原则

- **单一职责**：每个组件只负责一个功能点
- **高内聚低耦合**：组件内部逻辑紧凑，对外部依赖最小化
- **可复用性**：优先设计通用组件，再组合为业务组件
- **可测试性**：组件逻辑应便于编写单元测试

### 4.2 Props 接口定义

```typescript
interface ButtonProps {
  /** 按钮文字 */
  label: string;
  /** 点击回调 */
  onClick?: () => void;
  /** 按钮类型 */
  variant?: 'primary' | 'secondary' | 'danger';
  /** 是否禁用 */
  disabled?: boolean;
  /** 自定义样式类 */
  className?: string;
}
```

### 4.3 状态管理规范

- **组件内部状态**：使用 `useState`
- **跨组件共享状态**：使用 Context 或状态管理库
- **服务端状态**：使用 TanStack Query / SWR
- 避免过度状态管理，优先考虑组件组合

## 5. 样式规范

### 5.1 CSS 命名规范（BEM）

```css
.card {}
.card__header {}
.card__header--highlighted {}
.card__content {}
.card__button {}
```

### 5.2 响应式设计原则

- 采用移动优先（Mobile First）策略
- 使用相对单位（rem、em、%）
- 合理使用 CSS Grid 和 Flexbox
- 断点：`768px`（平板）、`1024px`（桌面）、`1440px`（大屏）

### 5.3 主题/变量规范

```css
:root {
  --color-primary: #1890ff;
  --color-success: #52c41a;
  --color-warning: #faad14;
  --color-error: #f5222d;
  --font-size-base: 14px;
  --spacing-unit: 8px;
  --border-radius: 4px;
}
```

## 6. 性能规范

### 6.1 代码分割

```javascript
const LazyComponent = React.lazy(() => import('./HeavyComponent'));
```

### 6.2 图片优化

- 使用 WebP 格式
- 提供多尺寸图片，使用 `srcset`
- 使用 CSS Sprite 合并小图标

### 6.3 懒加载策略

- 图片采用懒加载（Intersection Observer）
- 列表采用虚拟滚动（Virtual Scroll）
- 非首屏内容延迟加载

### 6.4 缓存策略

- 合理设置静态资源缓存（Cache-Control）
- 使用 Service Worker 实现离线缓存
- API 响应合理使用本地缓存

## 7. 安全规范

### 7.1 XSS 防护

- 所有用户输入必须经过转义处理
- React/Vue 默认防护，需注意 `dangerouslySetInnerHTML`
- 使用 DOMPurify 清理 HTML 内容

### 7.2 CSRF 防护

- 使用 SameSite Cookie
- 请求携带 CSRF Token
- 敏感操作使用 POST/PUT/DELETE 而非 GET

### 7.3 敏感信息处理

- **禁止**在前端代码中硬编码密钥、Token
- 敏感配置使用环境变量
- 日志中禁止记录密码、身份证等敏感信息

## 8. 测试规范

### 8.1 单元测试覆盖率要求

| 模块类型 | 最低覆盖率 |
|-|-|
| 工具函数/纯函数 | 90% |
| 自定义 Hooks | 80% |
| 业务组件 | 70% |
| 页面组件 | 60% |

### 8.2 集成测试策略

- 关键业务流程必须编写集成测试
- 使用 Cypress/Playwright 进行 E2E 测试
- CI/CD 流程中集成自动化测试

## 9. 部署规范

### 9.1 构建产物管理

- 生产构建移除所有调试代码和日志
- 使用 Tree-shaking 移除未使用代码
- 构建产物启用 Gzip/Brotli 压缩
- 使用 content hash 命名

### 9.2 环境变量管理

| 环境 | 说明 |
|-|-|
| development | 本地开发环境 |
| staging | 预发布环境 |
| production | 生产环境 |

- 使用 `.env.[environment]` 文件管理配置
- 敏感信息通过 CI/CD 变量注入
- 命名统一使用 `VITE_` 前缀
