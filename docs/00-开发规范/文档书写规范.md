## 2. 核心立场：把规范当纪律，不当框架

> **纪律（Discipline）** = 你在写每一篇文档时都必须自动遵守的约束。
> **框架（Framework）** = 你需要刻意去套用的模板或流程。

本规范定义的是 **纪律**——无论你写什么类型的文档，以下规则都会被自动化检查工具（Model-invoked Skills）自动执行。如果你违反了这些规则，文档将无法通过校验。

## 3. 文档元数据规范

### 3.1 文档头部信息块

【强制】每篇文档的 **前8行** 必须包含完整的文档说明表格：

```markdown
# 文档标题

## 1. 文档说明

| 属性 | 说明 |
|------|------|
| 文档版本 | V<主版本>.<次版本> |
| 生效日期 | YYYY-MM-DD |
| 适用范围 | 说明哪些团队/场景适用 |
| 作者 | 作者姓名/团队 |
```

### 3.2 版本号规则

【强制】采用语义化版本：

| 变更类型 | 版本号变更 | 示例 |
|---------|-----------|------|
| 不兼容的结构调整 | 主版本 +1 | V1.0 → V2.0 |
| 新增章节/内容补充 | 次版本 +1 | V1.0 → V1.1 |
| 错别字/格式修正 | 修订号 +1 | V1.0.0 → V1.0.1（写在变更记录中） |

## 5. Markdown 格式纪律

### 5.1 标题层级

【强制】标题层级必须严格递增，禁止跳级：

```
✅ 正确：# H1 → ## H2 → ### H3 → #### H4
❌ 错误：# H1 → ### H3（跳过了 H2）
```

【强制】每篇文档 **有且仅有一个** 一级标题（`#`），位于文档最开头。

### 5.2 中文排版

【强制】以下规则必须遵守：

| 规则 | ✅ 正确 | ❌ 错误 |
|------|--------|--------|
| 中英文之间加空格 | `使用 React 框架` | `使用React框架` |
| 中文与数字之间加空格 | `版本 2.0` | `版本2.0` |
| 数字与单位之间加空格 | `500 行` | `500行` |
| 中文标点后不加空格 | `你好，世界` | `你好， 世界` |
| 使用中文全角标点 | `，。；：""` | `,.;:""` |
| 代码/术语用反引号 | `npm install` | npm install |

### 5.3 列表与表格

【强制】列表必须以数字序号 `1. 2. 3.` 或 `-` 开头，同级对齐。

【强制】表格的表头必须与内容对齐，使用 `|------|------|` 分隔。表格首列若为"序号"，必须使用 `| 序号 |`。

### 5.4 代码块

【强制】所有代码块必须指定语言类型：

~~~markdown
✅ 正确：
```java
public class User { }
```

```sql
SELECT * FROM user;
```

❌ 错误：
```
public class User { }
```
~~~

### 5.5 文档结尾标记

【强制】每篇文档必须以以下格式结尾：

```markdown
---

**文档结束**

*本文档由 pangpang-doc 维护，解释权归架构组所有。*
```

## 6. 文档内容质量纪律

### 6.1 禁止出现的内容

【禁止】文档中不得出现以下占位符文本：

| 禁止内容 | 说明 |
|---------|------|
| `（待补充）` | 文档内容必须完整，禁止占位 |
| `本文档正在建设中` | 禁止发布半成品文档 |
| `TODO` / `FIXME` | 技术债必须在提交前解决 |
| 无实际内容的空章节 | 宁可删章节，不可留空壳 |

### 6.2 交叉引用规则

【推荐】引用项目内其他文档时，使用 **相对路径**，不要使用绝对 URL：

```markdown
✅ 正确：参考 [Git-工作流规范](../00-开发规范/Git-工作流规范.md)
❌ 错误：参考 https://github.com/xxx/docs/blob/main/...
```

### 6.3 图片与资源

【强制】文档中引用的图片必须存放于 `/assets/images/` 目录，使用相对路径引用：

```markdown
![架构图](../../assets/images/architecture-diagram.png)
```

【禁止】引用外部图片 URL（随时可能失效）。

## 7. 规范级别标记体系

【强制】文档中的规则必须使用以下三级标记之一，不可混用其他表述：

| 级别 | 标记格式 | 违反后果 | 检查方式 |
|------|---------|---------|---------|
| **强制** | `#### 【强制】规则名称` | 文档无法通过审查，被打回修改 | Model-invoked Skill 自动检查 |
| **推荐** | `#### 【推荐】规则名称` | 评审人提出改进建议，不阻塞合并 | 人工代码评审 |
| **禁止** | `#### 【禁止】规则名称` | 文档无法通过审查，被打回修改 | Model-invoked Skill 自动检查 |

### 7.1 规范级别使用示例

```markdown
#### 【强制】主分支保护

- `main` 和 `develop` 分支必须开启分支保护

#### 【推荐】分支清理

- 合并后及时删除本地和远程分支

#### 【禁止】

- 禁止在存在未解决冲突的情况下强行合并
```
