# 开发规范

## 1. 文档说明

| 属性 | 说明 |
|------|------|
| 文档版本 | V1.0 |
| 生效日期 | 2026-08-15 |
| 适用范围 | 公司所有研发团队（前端、后端、测试、架构） |

> **模块定位**：本模块承载团队协作的 **纪律标准**。所有代码必须符合这里的规范才能通过代码审查与 CI 校验。它不是建议，是强制约束。

### 2.2 每份规范的一句话用途

| 文档名 | 一句话用途 | 谁必须读 |

| `测试规范.md` | 单元/集成/端到端测试分层、覆盖率要求、测试命名 | 所有人 |
| `前端开发规范/` | HTML/CSS/JS/TS/Vue-React/工程化的前端全部纪律 | 前端开发 |
| `后端开发规范/` | Java 编码/异常/日志/RESTful API/数据库/SQL/JDK25/打包的后端全部纪律 | 后端开发 |

## 4. 与其他模块的关联

| 上下游 | 关联点 |
|--------|--------|
| **上游（定义约束的来源）** | 技术栈版本定义在 `../README.md`；本模块所有规范均以该技术栈为准 |
| **下游（规范的执行对象）** | 部署运维的 `../02-部署运维/` 遵循本模块的 Git 分支策略与打包规范；CI/CD 流水线执行本模块的检查规则 |
| **模板（落地的骨架）** | 项目模板 `../04-项目模板/` 中的 README/API/技术方案/数据库设计模板，均按 `文档书写规范.md` 的结构编写 |

## 5. 规范级别说明

| 级别 | 标识 | 含义 |
|------|------|------|
| **强制** | 【强制】 | 必须严格遵守，违反将导致代码无法通过审查或 CI 失败 |
| **推荐** | 【推荐】 | 建议遵守，有助于提高代码质量和团队协作效率 |
| **禁止** | 【禁止】 | 严格禁止，违反将导致代码无法通过审查或 CI 失败 |

> 所有规范均会被 Model-invoked Skills（纪律层）在提交时自动检查，详见 `../03-技术笔记/新技术调研/文档项目规则与技能体系设计.md`。

## 6. 落地检查清单

| 序号 | 检查项 | 检查方式 | 责任人 |
|------|--------|---------|--------|
| 1 | 新同事入职是否完成全部规范阅读（Git 工作流 + 命名 + 文档书写） | 入职 checklist | 团队负责人 |
| 2 | 代码审查是否按规范执行（审查清单 + 轮值） | 审查记录抽查 | 团队负责人 |
| 3 | 是否有违反规范的代码通过审查上线 | MR 回溯抽查 | 架构组 |
| 4 | 规范是否随技术栈升级同步更新（如 JDK25 新特性） | 版本变更记录 | 架构组 |
| 5 | 新成员是否知道去哪查规范（本模块导航） | 随机提问 | 团队负责人 |
