## 2. 命名规范

### 2.1 基本原则

| 对象 | 命名规则 | 示例 |
|-|-|-|
| 数据库 | 小写，下划线分隔 | `ecommerce_db` |
| 表名 | 小写，下划线分隔，模块_实体 | `user_account` / `order_detail` |
| 字段名 | 小写，下划线分隔 | `user_name` / `created_at` |
| 索引名 | `idx_` + 表名 + 字段 | `idx_user_account_email` |
| 唯一索引 | `uk_` + 表名 + 字段 | `uk_user_account_phone` |
| 外键名 | `fk_` + 表名 + 字段 | `fk_order_user_id` |

> 【禁止】中文命名、拼音命名、驼峰命名、保留字（如 select、table）、过长命名（超过 32 字符）

### 2.2 命名单词对照

| 含义 | 英文单词 | 禁用 |
|-|-|-|
| 用户 | user | customer（除非领域确定） |
| 账户 | account | — |
| 订单 | order | trade（除非支付链路） |
| 商品 | product | item/goods |
| 创建时间 | create_time | createDate |
| 更新时间 | update_time | updateDate |
| 删除时间 | deleted_time | — |
| 是否删除 | is_deleted | deleted / isDelete |
| 创建人 | created_by | create_by |
| 版本号 | version | ver |
| 租户ID | tenant_id | — |

## 3. 表结构设计

### 3.1 标准表结构模板

每张表参考包含以下公共字段：

```sql
CREATE TABLE `user_account` (
  -- 主键
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',

  -- 业务字段
  `username`    VARCHAR(50)  NOT NULL COMMENT '用户名',
  `email`       VARCHAR(100) NOT NULL COMMENT '邮箱',
  `phone`       VARCHAR(20) COMMENT '手机号',
  `status`      TINYINT NOT NULL DEFAULT 1 COMMENT '状态：1-正常 2-禁用',

  -- 公共字段
  `create_time`  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time`  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `created_by`   VARCHAR(64) COMMENT '创建人',
  `updated_by`   VARCHAR(64) COMMENT '更新人',
  `deleted_time` DATETIME COMMENT '删除时间（软删除）',
  `is_deleted`   TINYINT NOT NULL DEFAULT 0 COMMENT '是否删除：0-未删除 1-已删除',
  `version`      INT NOT NULL DEFAULT 0 COMMENT '乐观锁版本号',

  -- 索引
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_username` (`username`),
  KEY `idx_email` (`email`),
  KEY `idx_phone` (`phone`),
  KEY `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户账户表';
```

### 3.2 字段类型选择

| 数据类型 | 使用场景 | 示例 |
|-|-|-|
| TINYINT | 状态码、布尔值 | status、is_deleted |
| INT | 中等整数 | 用户 ID、订单数 |
| BIGINT | 主键、大数值 | id、金额（分） |
| VARCHAR(N) | 字符串，N 为最大长度 | username(50)、email(100) |
| TEXT | 长文本 | 描述、备注 |
| DATETIME | 日期时间 | created_at、expired_at |
| DATE | 日期 | birthday |
| DECIMAL(10,2) | 精确小数 | amount、price |
| JSON | 动态结构 | 扩展属性 |

> 【强制】金额字段必须使用 DECIMAL，禁止使用 FLOAT/DOUBLE（精度丢失问题）

## 4. 索引设计规范

### 4.1 索引类型选择

| 索引类型 | 使用场景 | 示例 |
|-|-|-|
| 主键索引 | 主键，唯一且非空 | `PRIMARY KEY (id)` |
| 唯一索引 | 唯一约束字段 | `UNIQUE KEY uk_phone (phone)` |
| 普通索引 | 查询加速 | `KEY idx_email (email)` |
| 联合索引 | 多字段组合查询 | `KEY idx_user_status (user_id, status)` |

### 4.2 联合索引设计原则

```sql
-- 场景：查询某用户的状态为正常的订单
-- 正确写法：等值在前，范围在后
KEY idx_user_status_time (user_id, status, created_at)

-- 查询：WHERE user_id = ? AND status = ? AND created_at > ?
--  ✅ 使用索引
```

### 4.3 索引设计检查

| 检查项 | 标准 |
|-|-|
| 单表索引数 | 不超过 5 个 |
| 单索引字段数 | 不超过 3 个 |
| 索引选择性 | 基数/总行数 > 10% 才建索引 |
| 联合索引 | 覆盖 80% 以上高频查询 |
| 冗余索引 | 已存在的单字段索引不应再单独建 |

## 6. 设计规范总结

| 推荐做法 | 避免做法 |
|-|-|
| 主键使用 BIGINT 自增 | 不用存储过程（难以维护） |
| 统一使用 utf8mb4 字符集 | 不用外键约束（应用层控制） |
| 所有表加公共字段 | 不用 TEXT 存短字符串 |
| 敏感数据加密存储 | 不用 NULL 字段（索引失效） |
| 定期归档历史数据 | 不用 FLOAT/DOUBLE 存金额 |
| 使用逻辑删除 | 不用触发器（隐式逻辑） |

## 7. DDL 示例

### 7.1 创建用户表

```sql
CREATE TABLE `user_account` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `username`    VARCHAR(50)  NOT NULL COMMENT '用户名',
  `password`    VARCHAR(128) NOT NULL COMMENT '密码（加密）',
  `email`       VARCHAR(100) NOT NULL COMMENT '邮箱',
  `phone`       VARCHAR(20) COMMENT '手机号',
  `avatar_url`  VARCHAR(255) COMMENT '头像URL',
  `status`      TINYINT NOT NULL DEFAULT 1 COMMENT '状态：1-正常 2-禁用',
  `created_at`  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at`  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `created_by`  VARCHAR(64) COMMENT '创建人',
  `updated_by`  VARCHAR(64) COMMENT '更新人',
  `deleted_at`  DATETIME COMMENT '删除时间',
  `is_deleted`  TINYINT NOT NULL DEFAULT 0 COMMENT '是否删除',
  `version`     INT NOT NULL DEFAULT 0 COMMENT '乐观锁版本号',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_username` (`username`),
  UNIQUE KEY `uk_email` (`email`),
  KEY `idx_phone` (`phone`),
  KEY `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户账户表';
```

### 7.2 创建订单表

```sql
CREATE TABLE `order_main` (
  `id`              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `order_no`        VARCHAR(32)  NOT NULL COMMENT '订单号',
  `user_id`         BIGINT UNSIGNED NOT NULL COMMENT '用户ID',
  `total_amount`    DECIMAL(12,2) NOT NULL DEFAULT 0 COMMENT '订单总金额',
  `pay_amount`      DECIMAL(12,2) NOT NULL DEFAULT 0 COMMENT '实付金额',
  `status`          TINYINT NOT NULL DEFAULT 0 COMMENT '订单状态',
  `pay_time`        DATETIME COMMENT '支付时间',
  `shipping_address` JSON COMMENT '收货地址信息',
  `remark`          VARCHAR(255) COMMENT '订单备注',
  `created_at`      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at`      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `created_by`      VARCHAR(64) COMMENT '创建人',
  `updated_by`      VARCHAR(64) COMMENT '更新人',
  `deleted_at`      DATETIME COMMENT '删除时间',
  `is_deleted`      TINYINT NOT NULL DEFAULT 0 COMMENT '是否删除',
  `version`         INT NOT NULL DEFAULT 0 COMMENT '乐观锁版本号',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_order_no` (`order_no`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单主表';
```
