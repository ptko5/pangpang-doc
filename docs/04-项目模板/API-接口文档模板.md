## 4. 基础信息

### 4.1 基础访问地址

| 环境 | Base URL |
|------|----------|
| 开发环境 | `http://dev.example.com/api/v1` |
| 测试环境 | `http://test.example.com/api/v1` |
| 预发环境 | `https://staging.example.com/api/v1` |
| 生产环境 | `https://api.example.com/v1` |

### 4.2 数据交换格式

- **请求方法**：严格遵循 [RESTful-API-设计规范](../00-开发规范/后端开发规范/RESTful-API-设计规范.md)
  - `GET`：读取资源
  - `POST`：创建资源
  - `PUT`：全量更新资源
  - `PATCH`：部分更新资源
  - `DELETE`：删除资源
- **请求体格式**：`Content-Type: application/json; charset=utf-8`（`GET` / `DELETE` 无请求体）
- **响应体格式**：统一 JSON 封装（见 §5）
- **字符编码**：UTF-8，无 BOM

### 4.3 鉴权方式

**默认方案：JWT Bearer Token**

```
Authorization: Bearer <access_token>
```

**获取 Token 接口**：参见 §6.1「用户登录」接口，成功响应中返回 `access_token`（有效期 2 小时）+ `refresh_token`（有效期 7 天）。

**Token 过期处理**：
- 接口返回业务码 `40101` → 前端调用 `/auth/refresh` 接口用 `refresh_token` 换新 `access_token`，自动重试原请求
- 接口返回业务码 `40102` → `refresh_token` 也过期，跳回登录页

**开放接口（无需鉴权）**：登录、刷新 Token、公开配置、公开字典数据、文件下载直链

### 4.4 通用请求头约定

| 请求头 | 必填 | 说明 | 示例 |
|--------|------|------|------|
| `Authorization` | 开放接口否/其他是 | Bearer Token | `Bearer eyJhbGciOi...` |
| `Content-Type` | POST/PUT/PATCH 是 | 固定值 | `application/json` |
| `Accept-Language` | 否 | 国际化语言（默认 `zh-CN`） | `zh-CN` / `en-US` |
| `X-Request-Id` | 否 | 请求唯一 ID（用于链路追踪，不传则服务端生成） | UUID v4 |
| `X-Tenant-Id` | 多租户场景是 | 租户 ID | `10086` |

### 4.5 接口版本管理策略

**URL 版本号**（本项目采用）：
- `https://api.example.com/v1/users` → v1 版本
- `https://api.example.com/v2/users` → v2 版本（不兼容变更必须升大版本）

**兼容变更**（不升版本，向后兼容）：
- 新增请求字段（服务端忽略未知字段）
- 新增响应字段
- 新增接口
- 新增枚举值（旧客户端未识别的枚举值需要有默认兜底）

**不兼容变更**（必须升大版本 v1→v2）：
- 删除或重命名接口 / 请求字段 / 响应字段
- 修改字段类型（如 `int` → `string`）
- 修改字段含义（如 `status=1` 从「启用」改为「停用」）
- 收紧校验规则（如原允许 `null` 的字段变为必填）

## 5. 统一响应结构

【强制】所有接口必须使用统一响应包装，**禁止直接返回裸数据**。

### 5.1 成功响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": { /* 业务数据，结构见各接口 */ },
  "requestId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "timestamp": 1786848000000
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `code` | int | 是 | 业务状态码：`0` = 成功，非 0 = 失败（见 §6 错误码表） |
| `message` | string | 是 | 简短描述：成功时固定 `success`，失败时显示用户可读的错误提示 |
| `data` | object / array / null | 是 | 业务响应数据，无数据时为 `null` |
| `requestId` | string | 是 | 请求唯一 ID（用于排查问题时提供给后端） |
| `timestamp` | long | 是 | 服务器响应时的毫秒级时间戳 |

### 5.2 分页列表响应格式

**GET 列表接口**的 `data` 字段必须统一为以下分页结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [ /* 业务对象数组 */ ],
    "pageNum": 1,
    "pageSize": 20,
    "total": 128,
    "pages": 7
  },
  "requestId": "...",
  "timestamp": 1786848000000
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `list` | array | 当前页数据列表 |
| `pageNum` | int | 当前页码（从 1 开始） |
| `pageSize` | int | 每页条数 |
| `total` | long | 总记录数 |
| `pages` | int | 总页数 |

### 5.3 失败响应格式

```json
{
  "code": 40001,
  "message": "参数校验失败：用户名不能为空",
  "data": {
    "fieldErrors": [
      { "field": "username", "message": "不能为空" }
    ]
  },
  "requestId": "...",
  "timestamp": 1786848000000
}
```

失败响应的 `data` 可选，用于携带调试信息（如参数校验明细、错误堆栈 hash 等）。

| 业务码范围 | 模块 | HTTP 状态码 | 说明 |
|-----------|------|------------|------|
| `0` | 通用 | 200 | 成功 |
| `40001 - 40099` | 参数校验 | 400 | 请求参数错误 |
| `40101 - 40199` | 鉴权 | 401 | 认证失败 / Token 过期 |
| `40301 - 40399` | 权限 | 403 | 无权限访问 |
| `40401 - 40499` | 资源不存在 | 404 | 资源未找到 |
| `40901 - 40999` | 业务冲突 | 409 | 重复创建 / 状态冲突 |
| `42901 - 42999` | 限流 | 429 | 请求过于频繁 |
| `50001 - 50099` | 系统 | 500 | 服务内部错误 |
| `10xxxx` | 用户模块 | 依场景定 | 10 开头 = 用户相关业务错误 |
| `20xxxx` | 订单模块 | 依场景定 | 20 开头 = 订单相关 |
| `30xxxx` | 支付模块 | 依场景定 | 30 开头 = 支付相关 |
| <!-- 使用者请替换：根据你的模块追加分段规则 --> | | | |

### 6.1 通用错误码明细

| 业务码 | HTTP 状态码 | message | 前端处理建议 |
|--------|------------|---------|------------|
| `40001` | 400 | 参数校验失败：<字段名> <原因> | 高亮对应表单项，显示 message |
| `40101` | 401 | Access Token 已过期 | 静默调用 `/auth/refresh` 换新 token，重试原请求 |
| `40102` | 401 | 登录已过期，请重新登录 | 清除本地 token，跳转登录页 |
| `40103` | 401 | 账号或密码错误 | 登录页 toast 提示，不跳转 |
| `40301` | 403 | 无权限访问该资源 | 显示 403 权限不足页，不建议重试 |
| `40401` | 404 | 请求的资源不存在 | 显示 404 页面或列表「暂无数据」 |
| `40901` | 409 | 资源已存在，请勿重复创建 | 表单提示用户该值已被占用 |
| `42901` | 429 | 请求过于频繁，请稍后重试 | toast + 按钮置灰 3 秒后允许重试 |
| `50001` | 500 | 服务繁忙，请稍后重试 | 展示「系统开小差」友好页 + 提供 requestId 便于排查 |

### 6.2 业务错误码示例（使用者请替换为你的实际业务错误码）

| 业务码 | HTTP 状态码 | message | 说明 |
|--------|------------|---------|------|
| `100001` | 400 | 用户名已被注册 | 用户模块 - 创建用户冲突 |
| `100002` | 400 | 手机号格式不正确 | 用户模块 - 参数校验 |
| `200001` | 409 | 订单状态不允许取消（已发货） | 订单模块 - 状态流转冲突 |
| `300001` | 400 | 余额不足，无法支付 | 支付模块 - 资金校验失败 |

## 7. 分页与查询约定

### 7.1 列表接口通用查询参数

所有 `GET /xxx` 列表接口必须支持以下查询参数（URL Query）：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `pageNum` | int | 否 | 1 | 页码，从 1 开始 |
| `pageSize` | int | 否 | 20 | 每页条数，最大 100（超过强制截断为 100） |
| `sortBy` | string | 否 | `createTime` | 排序字段，白名单校验（禁止任意字段排序防 SQL 注入） |
| `sortOrder` | string | 否 | `desc` | 排序方向：`asc` / `desc` |
| `keyword` | string | 否 | - | 模糊搜索关键字（匹配哪些字段由接口定义） |

### 7.2 时间范围查询约定

| 参数 | 类型 | 格式 | 说明 |
|------|------|------|------|
| `startTime` | string | `yyyy-MM-dd HH:mm:ss` | 起始时间（包含），如 `2026-08-01 00:00:00` |
| `endTime` | string | `yyyy-MM-dd HH:mm:ss` | 结束时间（包含），如 `2026-08-15 23:59:59` |

### 8.1 用户登录

#### ① 接口描述
用户使用用户名 + 密码登录，成功返回 JWT Access Token + Refresh Token + 用户基础信息。

#### ② 请求信息

| 项 | 值 |
|----|----|
| 方法 | `POST` |
| URL | `/auth/login` |
| 鉴权 | 否（开放接口） |

#### ③ 请求参数（Body）

| 字段 | 类型 | 必填 | 长度/范围 | 说明 |
|------|------|------|----------|------|
| `username` | string | 是 | 4~32 位 | 用户名 / 手机号 / 邮箱（三选一） |
| `password` | string | 是 | 8~64 位 | 密码（传输时前端可加密，传输层必须 HTTPS） |
| `captchaKey` | string | 否 | 32 位 | 图形验证码 key（连续 3 次失败后必传） |
| `captchaCode` | string | 否 | 4~6 位 | 图形验证码值 |

#### ④ 请求体示例

```json
{
  "username": "zhangsan",
  "password": "Abc@123456"
}
```

#### ⑤ 成功响应示例

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.xxx.yyy.zzz",
    "refreshToken": "eyJhbGciOi...另一个长字符串",
    "expiresIn": 7200,
    "user": {
      "id": 10001,
      "username": "zhangsan",
      "nickname": "张三",
      "avatar": "https://cdn.example.com/avatar/10001.png",
      "roles": ["ADMIN", "OPERATOR"]
    }
  },
  "requestId": "req-abc123",
  "timestamp": 1786848000000
}
```

#### ⑥ 成功响应字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `data.accessToken` | string | 访问令牌（2 小时有效，放入 `Authorization: Bearer` 请求头） |
| `data.refreshToken` | string | 刷新令牌（7 天有效，用于换新 accessToken） |
| `data.expiresIn` | int | accessToken 剩余秒数，便于前端定时刷新 |
| `data.user` | object | 登录用户基础信息（后端已鉴权通过，无需再查） |
| `data.user.roles` | array[string] | 权限角色编码，前端据此做路由/按钮级权限控制 |

#### ⑦ 失败场景与错误码

| 场景 | 业务码 | message |
|------|--------|---------|
| 用户不存在 | `100002` | 账号或密码错误 |
| 密码错误（第 1~2 次） | `40103` | 账号或密码错误 |
| 密码错误（连续 3 次以上） | `100003` | 密码错误次数过多，请输入图形验证码 |
| 账号被冻结 | `100004` | 账号已被冻结，请联系管理员 |
| 图形验证码过期或错误 | `40002` | 图形验证码错误或已过期 |

#### ⑧ 备注

- **幂等性**：同一账号 1 分钟内连续登录成功 ≤ 5 次，超过触发限流 `42901`
- **安全**：失败响应 message 统一提示「账号或密码错误」，禁止泄露「用户是否存在」这类区分性信息
- 登录成功后需记录审计日志（IP、User-Agent、登录时间、登录结果）

### 8.4 创建用户

#### ① 接口描述
管理员创建新用户（用户名/手机号全局唯一），创建成功后发送初始密码邮件。

#### ② 请求信息

| 项 | 值 |
|----|----|
| 方法 | `POST` |
| URL | `/users` |
| 鉴权 | 是，需要 `ADMIN` 角色 |

#### ③ 请求参数（Body）

| 字段 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| `username` | string | 是 | 4~32 位，字母/数字/下划线 | 登录用户名（全局唯一） |
| `nickname` | string | 是 | 2~32 位 | 显示昵称 |
| `phone` | string | 是 | 11 位大陆手机号 | 手机号（全局唯一） |
| `email` | string | 是 | 合法邮箱格式 | 邮箱（全局唯一，用于发初始密码邮件） |
| `roleIds` | array[long] | 是 | 至少 1 项 | 分配的角色 ID 列表 |
| `departmentId` | long | 是 | > 0 | 所属部门 ID |

#### ④ 请求体示例

```json
{
  "username": "lisi",
  "nickname": "李四",
  "phone": "13900139000",
  "email": "lisi@example.com",
  "roleIds": [2, 3],
  "departmentId": 2
}
```

#### ⑤ 成功响应示例（HTTP 201 Created）

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 10002
  },
  "requestId": "...",
  "timestamp": 1786848000000
}
```

#### ⑥ 失败场景

| 场景 | 业务码 | message |
