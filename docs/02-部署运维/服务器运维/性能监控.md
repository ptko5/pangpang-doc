# 性能监控

## 1. 文档说明

| 属性 | 说明 |
|------|------|
| 文档版本 | V1.0 |
| 生效日期 | 2026-08-15 |
| 适用范围 | 公司所有研发团队与运维（Prometheus + Grafana） |
| 作者 | 架构组 |

> **用途**：基于 Prometheus + Grafana + Spring Boot Actuator 的应用监控体系，包括指标采集、指标大盘、告警规则与通知渠道，实现线上可观测。

---

## 2. 监控架构

```text
Spring Boot (Actuator) ──> /actuator/prometheus
        │                          │
        └──> Prometheus(抓取) ──> 告警规则 ──> Alertmanager ──> 钉钉/邮件
                                   │
                              Grafana(大盘)
```

| 组件 | 职责 |
|------|------|
| Prometheus | 指标抓取与存储（TSDB） |
| Grafana | 可视化大盘与告警展示 |
| Alertmanager | 告警去重、分组、通知 |
| Actuator | 应用自身指标暴露 |

## 3. Spring Boot 暴露指标

### 3.1 依赖与配置

```gradle
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-actuator'
    implementation 'io.micrometer:micrometer-registry-prometheus'
}
```

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info,prometheus,metrics
  metrics:
    tags:
      application: ${spring.application.name}
```

> 【强制】生产必须暴露 `prometheus` 端点并开启健康检查，禁止关闭 Actuator。

### 3.2 验证

```bash
curl http://localhost:8080/actuator/prometheus | head -20
```

## 4. Prometheus 配置（prometheus.yml）

```yaml
global:
  scrape_interval: 15s

scrape_configs:
  - job_name: 'order-service'
    metrics_path: '/actuator/prometheus'
    static_configs:
      - targets: ['order-service:8080']

  - job_name: 'node-exporter'
    static_configs:
      - targets: ['10.0.0.1:9100']

rule_files:
  - 'rules/*.yml'
```

> 【推荐】部署 Node Exporter 采集宿主机指标（CPU/内存/磁盘），纳入同一 Prometheus。

## 5. 核心指标与大盘

### 5.1 关键指标

| 指标 | 说明 | 预警 |
|------|------|------|
| `process_cpu_usage` | 进程 CPU 使用率 | > 80% |
| `jvm_memory_used_bytes` | JVM 堆内存 | 持续 > 85% 堆 |
| `http_server_requests_seconds` | 接口耗时 | P95 > 500ms |
| `jvm_threads_live_threads` | 活跃线程 | 异常增长 |
| `node_filesystem_avail_bytes` | 磁盘可用 | < 20% |

### 5.2 Grafana 大盘（Dashboard）

```json
{
  "title": "Order Service Overview",
  "panels": [
    {
      "title": "QPS",
      "targets": [
        {
          "expr": "sum(rate(http_server_requests_seconds_count[1m])) by (uri)",
          "legendFormat": "{{uri}}"
        }
      ]
    }
  ]
}
```

> 【推荐】团队统一维护 Dashboard JSON，纳入仓库版本管理，避免各环境风格不一。

## 6. 告警规则（rules）

```yaml
groups:
  - name: order-service
    rules:
      - alert: ServiceDown
        expr: up{job="order-service"} == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "服务不可用 {{ $labels.job }}"

      - alert: HighErrorRate
        expr: |
          sum(rate(http_server_requests_seconds_count{status=~"5.."}[5m]))
            / sum(rate(http_server_requests_seconds_count[5m])) > 0.05
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "错误率超 5%"

      - alert: DiskFull
        expr: (node_filesystem_avail_bytes / node_filesystem_size_bytes) * 100 < 20
        for: 10m
        labels:
          severity: warning
```

## 7. 通知渠道（Alertmanager）

```yaml
route:
  group_by: ['alertname']
  group_wait: 30s
  group_interval: 5m
  repeat_interval: 4h
  receiver: 'dingtalk'

receivers:
  - name: 'dingtalk'
    webhook_configs:
      - url: 'https://oapi.dingtalk.com/robot/send?access_token=xxx'
        send_resolved: true
```

> 【强制】告警必须分级（critical/warning），配置去重与抑制，避免告警风暴；关键告警必须送达值班人。

## 8. 常见问题排查

| 问题现象 | 原因 | 解决方案 |
|---------|------|---------|
| Prometheus 无数据 | 抓取路径/端口错误 | 核对 `metrics_path` 与 Target 状态 |
| 指标丢失 | Actuator 未暴露 | 检查 `exposure.include` |
| 告警风暴 | 规则/抑制缺失 | 配置 `repeat_interval` 与抑制规则 |
| 大盘无图 | PromQL 错误 | 在 Prometheus 中调试查询 |
| 时间不同步 | 集群时钟漂移 | NTP 校准 |
