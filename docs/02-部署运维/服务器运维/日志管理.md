## 2. 采集架构

```text
应用(JSON 日志) ──> Filebeat ──> Logstash(清洗) ──> Elasticsearch ──> Kibana
                                                      │
                                                  告警规则 ──> 钉钉
```

| 组件 | 职责 |
|------|------|
| Filebeat | 轻量日志采集（推荐） |
| Logstash | 清洗、过滤、转换 |
| Elasticsearch | 存储与检索 |
| Kibana | 查询与可视化 |
| 告警 | Watcher / ElastAlert / Grafana |

## 3. 日志规范（写入方）

> 【强制】应用日志必须输出 **JSON 格式**，包含 `timestamp`、`level`、`traceId`、`service`、`message` 字段，敏感信息脱敏。

```json
{
  "timestamp": "2026-08-15T10:30:00.123+08:00",
  "level": "ERROR",
  "traceId": "a1b2c3d4e5f6",
  "service": "order-service",
  "message": "create order failed",
  "exception": "BusinessException: stock insufficient"
}
```

### 3.1 Spring Boot JSON 配置示例

```xml
<!-- logback-spring.xml 使用 logstash-logback-encoder 输出 JSON -->
<configuration>
    <appender name="JSON" class="ch.qos.logback.core.ConsoleAppender">
        <encoder class="net.logstash.logback.encoder.LogstashEncoder">
            <customFields>{"service":"order-service"}</customFields>
            <includeMdcKeyName>traceId</includeMdcKeyName>
        </encoder>
    </appender>
    <root level="INFO">
        <appender-ref ref="JSON"/>
    </root>
</configuration>
```

> 【强制】日志必须携带 `traceId`（通过 MDC 透传），禁止记录身份证、密码、Token 等敏感字段。

## 4. Filebeat 采集配置（filebeat.yml）

```yaml
filebeat.inputs:
  - type: container
    paths:
      - '/var/lib/docker/containers/*/*.log'
    json.keys_under_root: true

output.logstash:
  hosts: ['logstash:5044']
```

```bash
# 启动
docker run -d \
  --name filebeat \
  -v /var/lib/docker/containers:/var/lib/docker/containers:ro \
  docker.elastic.co/beats/filebeat:8.15.0
```

## 5. Logstash 清洗配置（logstash.conf）

```conf
input {
  beats {
    port => 5044
  }
}

filter {
  if [level] == "ERROR" {
    mutate { add_tag => ["error"] }
  }
}

output {
  elasticsearch {
    hosts => ["http://elasticsearch:9200"]
    index => "app-logs-%{+YYYY.MM.dd}"
  }
}
```

> 【推荐】按天分索引 `app-logs-yyyy.MM.dd`，便于冷热分离与生命周期管理（ILM）。

## 6. Kibana 查询

### 6.1 常用查询语法

| 场景 | 查询 |
|------|------|
| 查询某服务 ERROR | `service: "order-service" AND level: "ERROR"` |
| 按 TraceId 追踪全链路 | `traceId: "a1b2c3d4e5f6"` |
| 查询最近 5 分钟 | `@timestamp >= now-5m` |
| 模糊匹配 | `message: *timeout*` |
| 排除字段 | `level: ERROR AND NOT message: 健康检查` |

### 6.2 追踪示例

1. 从监控平台复制一条异常 `traceId`
2. 在 Kibana 搜索 `traceId: "xxx"`，按 `@timestamp` 排序
3. 依次查看调用链上下游日志，定位根因

> 【推荐】建立「TraceId 一键追踪」视图模板，沉淀为团队排查 SOP。

## 7. 日志告警

| 告警类型 | 规则示例 |
|---------|---------|
| ERROR 频率 | 5 分钟内 ERROR > 100 条 |
| 特定异常 | 匹配 `NullPointerException` / `Connection refused` |
| 日志堆积 | 采集速率骤降/上升异常 |
| 关键词 | 支付失败、库存不足等业务关键词 |

```text
# ElastAlert 规则示例（rate 告警）
rule:
  type: frequency
  index: app-logs-*
  num_events: 100
  timeframe:
    minutes: 5
  filter:
    - query:
        query_string:
          query: 'level: ERROR AND service: order-service'
alert:
  - 'elastalert_modules.dingtalk'
```

> 【强制】日志告警必须收敛（去重、分组），避免告警风暴影响响应。

## 8. 日志生命周期与安全

```bash
# 通过 ILM 策略保留 30 天，冷数据归档/删除
PUT _ilm/policy/app-logs-policy
{
  "policy": {
    "phases": {
      "hot":  { "min_age": "0d", "actions": {} },
      "delete": { "min_age": "30d", "actions": { "delete": {} } }
    }
  }
}
```

> 【推荐】生产日志保留 30 天（按合规要求可延长）；删除前确认无需审计。
