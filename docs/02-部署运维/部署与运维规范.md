## 2. 环境规范

### 2.1 环境划分

#### 【强制】环境层级

| 环境 | 用途 | 说明 |
|------|------|------|
| **开发环境** | 开发调试 | 本地或开发服务器 |
| **测试环境** | 功能测试 | 独立测试服务器 |
| **预发环境** | 预发布验证 | 与生产环境一致 |
| **生产环境** | 正式运行 | 线上服务器 |

### 2.2 环境隔离

#### 【强制】环境隔离规范

| 隔离项 | 说明 |
|--------|------|
| **网络隔离** | 各环境独立网络 |
| **数据库隔离** | 各环境独立数据库 |
| **配置隔离** | 各环境独立配置 |
| **域名隔离** | 各环境独立域名 |

#### ✅ 正确示例

```
开发环境: dev.example.com
测试环境: test.example.com
预发环境: staging.example.com
生产环境: www.example.com
```

## 3. 构建规范

### 3.1 后端构建规范

#### 【强制】Maven构建

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0">
    <modelVersion>4.0.0</modelVersion>

    <groupId>com.example</groupId>
    <artifactId>user-service</artifactId>
    <version>1.0.0</version>
    <packaging>jar</packaging>

    <properties>
        <java.version>25</java.version>
        <maven.compiler.source>25</maven.compiler.source>
        <maven.compiler.target>25</maven.compiler.target>
        <maven.compiler.release>25</maven.compiler.release>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    </properties>

    <build>
        <plugins>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-compiler-plugin</artifactId>
                <version>3.13.0</version>
                <configuration>
                    <source>25</source>
                    <target>25</target>
                    <release>25</release>
                </configuration>
            </plugin>

            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
                <version>4.0.0</version>
                <configuration>
                    <excludes>
                        <exclude>
                            <groupId>org.projectlombok</groupId>
                            <artifactId>lombok</artifactId>
                        </exclude>
                    </excludes>
                </configuration>
                <executions>
                    <execution>
                        <goals>
                            <goal>repackage</goal>
                        </goals>
                    </execution>
                </executions>
            </plugin>
        </plugins>
    </build>
</project>
```

## 4. Docker规范

### 4.1 Dockerfile规范

#### 【强制】多阶段构建

```dockerfile
# 构建阶段
FROM openjdk:25-jdk-slim AS builder

WORKDIR /app

COPY pom.xml .
COPY src ./src

RUN mvn clean package -DskipTests

# 运行阶段
FROM openjdk:25-jdk-slim

WORKDIR /app

COPY --from=builder /app/target/*.jar app.jar

EXPOSE 8080

ENTRYPOINT ["java", "-jar", "app.jar", "--spring.profiles.active=prod"]
```

### 4.2 镜像命名规范

#### 【强制】镜像命名

| 规则 | 示例 |
|------|------|
| **镜像名** | `{业务}-{模块}-service` |
| **标签** | `{版本号}-{环境}` |

#### ✅ 正确示例

```bash
docker build -t registry.example.com/user-service:1.0.0-prod .
docker push registry.example.com/user-service:1.0.0-prod
```

## 5. Kubernetes规范

### 5.1 Deployment规范

#### 【强制】Deployment配置

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: user-service
  namespace: example
  labels:
    app: user-service
    version: 1.0.0
spec:
  replicas: 3
  selector:
    matchLabels:
      app: user-service
  strategy:
    rollingUpdate:
      maxSurge: 25%
      maxUnavailable: 25%
    type: RollingUpdate
  template:
    metadata:
      labels:
        app: user-service
        version: 1.0.0
    spec:
      containers:
        - name: user-service
          image: registry.example.com/user-service:1.0.0-prod
          ports:
            - containerPort: 8080
              protocol: TCP
          resources:
            limits:
              memory: 512Mi
              cpu: "1"
            requests:
              memory: 256Mi
              cpu: "0.5"
          livenessProbe:
            httpGet:
              path: /health
              port: 8080
            initialDelaySeconds: 30
            periodSeconds: 10
            timeoutSeconds: 5
          readinessProbe:
            httpGet:
              path: /health
              port: 8080
            initialDelaySeconds: 10
            periodSeconds: 5
            timeoutSeconds: 3
          env:
            - name: SPRING_PROFILES_ACTIVE
              value: prod
            - name: NACOS_SERVER_ADDR
              value: nacos.example.com:8848
          volumeMounts:
            - name: config
              mountPath: /app/config
      volumes:
        - name: config
          configMap:
            name: user-service-config
```

## 6. CI/CD规范

### 6.1 CI/CD流程

#### 【强制】CI/CD流程

```
代码提交 → 代码审查 → 构建 → 单元测试 → 集成测试 → 镜像构建 → 镜像推送 → 部署到测试环境 → 测试通过 → 部署到预发环境 → 验证通过 → 部署到生产环境
```

### 6.2 GitHub Actions配置

#### 【推荐】CI配置

```yaml
name: CI/CD

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up JDK 25
        uses: actions/setup-java@v4
        with:
          java-version: '25'
          distribution: 'temurin'

      - name: Build with Maven
        run: mvn clean package -DskipTests

      - name: Run unit tests
        run: mvn test

      - name: Build Docker image
        run: docker build -t registry.example.com/user-service:${{ github.sha }} .

      - name: Push Docker image
        run: |
          echo "${{ secrets.DOCKER_PASSWORD }}" | docker login registry.example.com -u "${{ secrets.DOCKER_USERNAME }}" --password-stdin
          docker push registry.example.com/user-service:${{ github.sha }}

  deploy-test:
    needs: build
    runs-on: ubuntu-latest
    environment: test
    steps:
      - uses: actions/checkout@v4
      - name: Deploy to test
        uses: appleboy/k8s-deploy-action@master
        with:
          kubeconfig: ${{ secrets.KUBE_CONFIG }}
          namespace: example-test
          deployment: user-service
          image: registry.example.com/user-service:${{ github.sha }}

  deploy-prod:
    needs: deploy-test
    runs-on: ubuntu-latest
    environment: prod
    steps:
      - uses: actions/checkout@v4
      - name: Deploy to prod
        uses: appleboy/k8s-deploy-action@master
        with:
          kubeconfig: ${{ secrets.KUBE_CONFIG }}
          namespace: example-prod
          deployment: user-service
          image: registry.example.com/user-service:${{ github.sha }}
```

## 9. 日志管理规范

### 9.1 日志格式

#### 【强制】日志格式

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <property name="LOG_PATH" value="/var/log/example"/>
    <property name="APP_NAME" value="user-service"/>

    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>${LOG_PATH}/${APP_NAME}.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
            <fileNamePattern>${LOG_PATH}/${APP_NAME}.%d{yyyy-MM-dd}.log</fileNamePattern>
            <maxHistory>30</maxHistory>
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <root level="INFO">
        <appender-ref ref="CONSOLE"/>
        <appender-ref ref="FILE"/>
    </root>

    <logger name="com.example.user" level="DEBUG"/>
</configuration>
```

## 10. 运维脚本规范

### 10.1 启动脚本

#### 【强制】启动脚本

```bash
#!/bin/bash

APP_NAME="user-service"
APP_DIR="/opt/app"
JAR_FILE="${APP_DIR}/${APP_NAME}.jar"
LOG_FILE="${APP_DIR}/logs/${APP_NAME}.log"

mkdir -p "${APP_DIR}/logs"

echo "Starting ${APP_NAME}..."

nohup java -jar ${JAR_FILE} \
  --spring.profiles.active=prod \
  --server.port=8080 \
  > ${LOG_FILE} 2>&1 &

echo "${APP_NAME} started successfully"
```

### 10.2 停止脚本

#### 【强制】停止脚本

```bash
#!/bin/bash

APP_NAME="user-service"

PID=$(ps -ef | grep ${APP_NAME} | grep -v grep | awk '{print $2}')

if [ -z "${PID}" ]; then
    echo "${APP_NAME} is not running"
    exit 1
fi

echo "Stopping ${APP_NAME}..."
kill -TERM ${PID}

sleep 5

PID=$(ps -ef | grep ${APP_NAME} | grep -v grep | awk '{print $2}')

if [ -z "${PID}" ]; then
    echo "${APP_NAME} stopped successfully"
else
    echo "Force stopping ${APP_NAME}..."
    kill -9 ${PID}
    echo "${APP_NAME} force stopped"
fi
```

### 10.3 健康检查脚本

#### 【强制】健康检查脚本

```bash
#!/bin/bash

APP_NAME="user-service"
HEALTH_URL="http://localhost:8080/health"

RESPONSE=$(curl -s -o /dev/null -w "%{http_code}" ${HEALTH_URL})

if [ "${RESPONSE}" = "200" ]; then
    echo "${APP_NAME} is healthy"
    exit 0
else
    echo "${APP_NAME} is unhealthy, response code: ${RESPONSE}"
    exit 1
fi
```
