# 部署运维

## 1. 文档说明

| 属性 | 说明 |
|------|------|
| 文档版本 | V1.0 |
| 生效日期 | 2026-08-15 |
| 适用范围 | 公司所有项目的部署实施、环境运维、线上值班相关人员（开发 + 测试 + 运维） |
| 作者 | 架构组 |

> **模块定位**：本模块是从「代码提交」到「线上稳定运行」的完整手册。覆盖容器化构建 → 编排部署 → 云原生进阶 → 服务器日常运维 → CI/CD 自动化 → 规范与 SOP 的全链路能力。

## 3. 快速导航表（按场景进入）

> 把以下表格当作「运维问题的入口地图」，遇到什么场景直接跳到对应文档。

### 场景 A：我要把本地的 Spring Boot 应用跑成 Docker 容器

| 步骤 | 去哪看 | 做什么 |
|------|-------|--------|
| 1 | [Docker-基础入门.md](./Docker-部署指南/Docker-基础入门.md) | 搞懂镜像/容器/Dockerfile 概念，确认 Docker 已安装 |
| 2 | **[Dockerfile-编写规范.md](./Docker-部署指南/Dockerfile-编写规范.md)** | 按规范写生产级 Dockerfile（推荐 JDK 25 + 多阶段构建） |
| 3 | [Docker-常用命令.md](./Docker-部署指南/Docker-常用命令.md) | 用 `docker build` / `docker run` 把容器跑起来 |
| 4 | **[Docker-Compose-部署实战.md](./Docker-部署指南/Docker-Compose-部署实战.md)** | 需要 MySQL/Redis/Nginx 配套时，用 Compose 一键拉起整套 |

### 场景 B：我要部署到 Kubernetes 集群

| 步骤 | 去哪看 | 做什么 |
|------|-------|--------|
| 1 | **[Kubernetes-入门.md](./云原生/Kubernetes-入门.md)** | 通读核心概念 → 写 Deployment/Service/Ingress YAML |
| 2 | [Kubernetes-入门.md § kubectl 命令速查](./云原生/Kubernetes-入门.md) | 用 `kubectl apply` 发布；查 Pod 状态、看日志、进容器排错 |
| 3 | **[Helm-Chart-使用.md](./云原生/Helm-Chart-使用.md)** | 多环境/多服务部署时，把 YAML 抽成 Helm Chart 模板化管理 |
| 4 | [部署与运维规范.md § 灰度发布策略](./部署与运维规范.md) | 正式发布必须遵守金丝雀流程 + 回滚预案 |

### 场景 C：线上服务器有问题，我要登录机器排查

| 现象 | 先看哪份文档 | 第一反应动作 |
|------|-------------|-------------|
| CPU 飙升 / 负载高 | [Linux-常用命令.md § 性能诊断类](./服务器运维/Linux-常用命令.md) | `top` / `htop` → 找占用最高的进程 |
| 内存 OOM / 内存泄漏 | [性能监控.md](./服务器运维/性能监控.md) + JVM 调优案例 | `free -h` → `jmap` 堆 dump → MAT 分析 |
| 接口超时 / 报错 | [日志管理.md](./服务器运维/日志管理.md) | 按 TraceId 在 Kibana 搜完整链路日志 |
| 磁盘满了 / 大文件 | [Linux-常用命令.md § 文件与目录类](./服务器运维/Linux-常用命令.md) | `df -h` → `du -sh /*` → `lsof | grep deleted` 查僵尸句柄 |
| 网络不通 / 端口被占 | [Linux-常用命令.md § 网络类](./服务器运维/Linux-常用命令.md) | `ss -tlnp` 查端口 → `ping` / `telnet` / `curl` 逐层排查 |

| 测试环境已用 Docker Compose 一键拉起整套依赖 | 【推荐】 | □1 □2 □3 □4 □5 | `{如：已落地，新人入职 30 分钟跑通全链路}` |
| 生产环境已部署 Kubernetes（或等价容器编排平台） | 【强制】 | □1 □2 □3 □4 □5 | `{如：生产用 ACK，测试用 Kind，CI 用 K3s}` |
| 所有 K8s 资源均通过 Helm Chart 管理（禁止裸 apply YAML） | 【推荐】 | □1 □2 □3 □4 □5 | `{如：已覆盖核心服务，工具服务待迁移}` |
