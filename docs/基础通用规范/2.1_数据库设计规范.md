## 2. 数据库命名规范

### 2.1 数据库命名

#### 【强制】数据库命名规则

- 使用 **小写英文**
- 使用 **下划线** 分隔单词
- 命名格式：`{业务线}_{模块}_{环境}`

#### ✅ 正确示例

```sql
CREATE DATABASE IF NOT EXISTS example_user DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE IF NOT EXISTS example_order DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE IF NOT EXISTS example_pay DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

#### ❌ 错误示例

```sql
CREATE DATABASE ExampleUser;        -- 错误：使用大驼峰
CREATE DATABASE exampleUser;        -- 错误：使用小驼峰
CREATE DATABASE EXAMPLE_USER;       -- 错误：使用全大写
```

### 2.2 表命名

#### 【强制】表命名规则

- 使用 **小写英文**
- 使用 **下划线** 分隔单词
- 使用 **复数形式**
- 命名格式：`{业务模块}_{功能描述}`

#### ✅ 正确示例

```sql
CREATE TABLE user ( ... );
CREATE TABLE `order` ( ... );
CREATE TABLE user_role ( ... );
CREATE TABLE order_item ( ... );
CREATE TABLE system_config ( ... );
CREATE TABLE audit_log ( ... );
```

#### ❌ 错误示例

```sql
CREATE TABLE User ( ... );           -- 错误：使用大写
CREATE TABLE USER ( ... );           -- 错误：使用全大写
CREATE TABLE t_user ( ... );         -- 错误：添加冗余前缀
CREATE TABLE userInfo ( ... );       -- 错误：使用小驼峰
CREATE TABLE user_info_tbl ( ... );  -- 错误：添加冗余后缀
```

### 2.3 字段命名

#### 【强制】字段命名规则

- 使用 **小写英文**
- 使用 **下划线** 分隔单词
- 使用 **单数形式**
- 禁止使用保留字

#### ✅ 正确示例

```sql
id, username, email, password, status, created_at, updated_at
user_id, order_id, product_id, role_id
is_active, has_permission, can_delete
```

#### ❌ 错误示例

```sql
ID, UserName, user_name_           -- 错误：使用大写或多余下划线
userName, orderId                  -- 错误：使用小驼峰
delete, update, order, select      -- 错误：使用保留字
```

### 2.4 索引命名

#### 【强制】索引命名规则

| 索引类型 | 命名格式 | 示例 |
|---------|---------|------|
| **主键** | `PRIMARY` | 数据库默认 |
| **唯一索引** | `uk_{表名}_{字段名}` | `uk_user_email` |
| **普通索引** | `idx_{表名}_{字段名}` | `idx_user_status` |
| **联合索引** | `idx_{表名}_{字段1}_{字段2}` | `idx_order_user_created` |

#### ✅ 正确示例

```sql
ALTER TABLE user ADD UNIQUE INDEX uk_user_email (email);
ALTER TABLE user ADD INDEX idx_user_status (status);
ALTER TABLE `order` ADD INDEX idx_order_user_created (user_id, created_at);
```

## 3. 字段设计规范

### 3.1 字段类型选择

#### 【强制】字段类型规范

| 数据类型 | 用途 | 说明 |
|---------|------|------|
| **INT** | 整数 | ID、数量等 |
| **BIGINT** | 大整数 | 分布式ID、时间戳等 |
| **VARCHAR** | 变长字符串 | 用户名、邮箱等 |
| **TEXT** | 长文本 | 描述、内容等 |
| **DATETIME** | 日期时间 | 创建时间、更新时间等 |
| **DECIMAL** | 精确小数 | 金额、价格等 |
| **ENUM** | 枚举 | 状态字段 |
| **JSON** | JSON数据 | 复杂结构数据 |
| **TINYINT** | 布尔值 | 0/1表示布尔状态 |

#### ✅ 正确示例

```sql
CREATE TABLE user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    username VARCHAR(50) NOT NULL COMMENT '用户名',
    email VARCHAR(100) NOT NULL COMMENT '邮箱',
    password VARCHAR(255) NOT NULL COMMENT '密码（加密存储）',
    status TINYINT DEFAULT 1 COMMENT '状态：0-禁用，1-启用',
    balance DECIMAL(10, 2) DEFAULT 0.00 COMMENT '余额',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间'
);
```

### 3.2 字段约束

#### 【强制】字段约束规范

| 约束 | 说明 | 使用场景 |
|------|------|---------|
| **NOT NULL** | 非空约束 | 必填字段 |
| **DEFAULT** | 默认值约束 | 有默认值的字段 |
| **UNIQUE** | 唯一约束 | 唯一标识字段 |
| **PRIMARY KEY** | 主键约束 | 主键字段 |
| **FOREIGN KEY** | 外键约束 | 关联字段 |
| **CHECK** | 检查约束 | 字段值范围限制 |

#### ✅ 正确示例

```sql
CREATE TABLE user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    username VARCHAR(50) NOT NULL COMMENT '用户名',
    email VARCHAR(100) NOT NULL UNIQUE COMMENT '邮箱',
    status TINYINT NOT NULL DEFAULT 1 COMMENT '状态：0-禁用，1-启用',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间'
);
```

### 3.3 时间字段规范

#### 【强制】时间字段规范

| 字段名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `created_at` | DATETIME | CURRENT_TIMESTAMP | 创建时间 |
| `updated_at` | DATETIME | CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |

#### ✅ 正确示例

```sql
CREATE TABLE user (
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间'
);
```

## 4. 索引设计规范

### 4.1 主键设计

#### 【强制】主键规范

- 主键使用 **BIGINT** 类型
- 主键使用 **自增** 或 **分布式ID**
- 禁止使用业务字段作为主键

#### ✅ 正确示例

```sql
CREATE TABLE user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    ...
);

-- 使用分布式ID
CREATE TABLE order (
    id BIGINT PRIMARY KEY COMMENT '主键ID（分布式ID）',
    ...
);
```

#### ❌ 错误示例

```sql
CREATE TABLE user (
    username VARCHAR(50) PRIMARY KEY COMMENT '用户名为主键'  -- 错误：使用业务字段作为主键
);
```

### 4.2 索引使用场景

#### 【强制】索引创建场景

| 场景 | 是否需要索引 | 说明 |
|------|-------------|------|
| WHERE条件字段 | ✅ 需要 | 加速查询过滤 |
| ORDER BY字段 | ✅ 需要 | 避免排序开销 |
| JOIN关联字段 | ✅ 需要 | 加速关联查询 |
| GROUP BY字段 | ✅ 需要 | 加速分组 |
| 高基数字段 | ✅ 需要 | 区分度高的字段 |
| 低基数字段 | ❌ 不需要 | 区分度低，索引效果差 |

### 4.3 联合索引

#### 【推荐】联合索引设计

- 遵循 **最左前缀原则**
- 将 **区分度高** 的字段放在前面
- 将 **常用过滤** 的字段放在前面

#### ✅ 正确示例

```sql
-- 查询：WHERE user_id = ? AND status = ? ORDER BY created_at DESC
CREATE INDEX idx_order_user_status_created ON `order` (user_id, status, created_at);

-- 查询：WHERE username LIKE ? AND status = ?
CREATE INDEX idx_user_status_username ON user (status, username);
```

#### ❌ 错误示例

```sql
-- 错误：顺序错误，无法利用最左前缀
CREATE INDEX idx_order_created_status_user ON `order` (created_at, status, user_id);
```

### 4.4 索引禁忌

#### 【禁止】索引滥用

| 禁忌 | 原因 |
|------|------|
| **过多索引** | 降低写入性能，占用存储空间 |
| **索引字段过多** | 索引体积大，维护成本高 |
| **重复索引** | 浪费资源，无实际收益 |
| **低基数字段建索引** | 索引效果差，不如全表扫描 |
| **频繁更新字段建索引** | 每次更新都要维护索引 |

## 5. 表设计规范

### 5.1 表结构模板

#### 【强制】标准表结构

```sql
CREATE TABLE `{表名}` (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    -- 业务字段...
    status TINYINT NOT NULL DEFAULT 1 COMMENT '状态：0-禁用，1-启用',
    created_by BIGINT DEFAULT NULL COMMENT '创建人ID',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_by BIGINT DEFAULT NULL COMMENT '更新人ID',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    deleted TINYINT NOT NULL DEFAULT 0 COMMENT '删除标记：0-未删除，1-已删除',
    INDEX idx_status (status),
    INDEX idx_created_at (created_at),
    INDEX idx_deleted (deleted)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='{表描述}';
```

### 5.2 软删除规范

#### 【强制】软删除字段

| 字段名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `deleted` | TINYINT | 0 | 删除标记：0-未删除，1-已删除 |

#### ✅ 正确示例

```sql
-- 查询时过滤已删除数据
SELECT * FROM user WHERE deleted = 0;

-- 删除时更新标记
UPDATE user SET deleted = 1, updated_at = NOW() WHERE id = 1;
```

### 5.3 关联表设计

#### 【强制】多对多关联表

```sql
CREATE TABLE user_role (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    user_id BIGINT NOT NULL COMMENT '用户ID',
    role_id BIGINT NOT NULL COMMENT '角色ID',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    UNIQUE INDEX uk_user_role (user_id, role_id),
    INDEX idx_user_id (user_id),
    INDEX idx_role_id (role_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户角色关联表';
```

## 6. SQL编写规范

### 6.1 SQL格式规范

#### 【强制】SQL格式

```sql
-- ✅ 正确格式
SELECT 
    u.id, 
    u.username, 
    u.email, 
    u.created_at
FROM user u
WHERE 
    u.status = 1
    AND u.deleted = 0
ORDER BY u.created_at DESC
LIMIT 10 OFFSET 0;
```

#### 【强制】关键字大写

```sql
SELECT, FROM, WHERE, AND, OR, ORDER BY, GROUP BY, HAVING, LIMIT, INSERT, UPDATE, DELETE
```

### 6.2 SQL性能规范

#### 【强制】禁止SELECT *

```sql
-- ✅ 正确
SELECT id, username, email FROM user;

-- ❌ 错误
SELECT * FROM user;
```

#### 【强制】禁止全表扫描

```sql
-- ❌ 错误：无WHERE条件
SELECT * FROM user;

-- ❌ 错误：LIKE以%开头，无法使用索引
SELECT * FROM user WHERE username LIKE '%test%';
```

#### 【推荐】分页查询

```sql
-- ✅ 正确：使用主键分页
SELECT id, username, email
FROM user
WHERE id > #{lastId}
ORDER BY id ASC
LIMIT 10;

-- ✅ 正确：使用LIMIT OFFSET（小偏移量）
SELECT id, username, email
FROM user
WHERE status = 1
ORDER BY created_at DESC
LIMIT #{pageSize} OFFSET #{offset};
```

## 8. 数据脱敏规范

### 8.1 敏感数据定义

| 数据类型 | 说明 | 示例 |
|---------|------|------|
| **个人身份信息** | 姓名、身份证号、手机号 | 张三、110101199001011234 |
| **联系方式** | 邮箱、地址 | test@example.com |
| **金融信息** | 银行卡号、密码 | 6222021234567890 |
| **隐私信息** | 性别、年龄、家庭信息 | 男、25岁 |

### 8.2 脱敏规则

#### 【强制】脱敏规则

| 数据类型 | 脱敏规则 | 示例 |
|---------|---------|------|
| **姓名** | 保留姓氏，中间用*代替 | 张** |
| **手机号** | 保留前3位和后4位 | 138****1234 |
| **邮箱** | 保留@前1位和域名 | t***@example.com |
| **身份证号** | 保留前6位和后4位 | 110101****1234 |
| **银行卡号** | 保留前4位和后4位 | 6222****1234 |

### 8.3 脱敏实现

#### 【推荐】SQL级别脱敏

```sql
-- 查询时脱敏
SELECT 
    id,
    CONCAT(LEFT(username, 1), '***') AS username_masked,
    CONCAT(LEFT(email, 1), '***', SUBSTRING_INDEX(email, '@', -1)) AS email_masked,
    CONCAT(LEFT(phone, 3), '****', RIGHT(phone, 4)) AS phone_masked
FROM user;
```
